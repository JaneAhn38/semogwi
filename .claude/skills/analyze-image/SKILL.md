# analyze-image: 사진 → image-analysis.md (사용자 확인)

사진에서 **무엇이 보이는지**를 정리하고, 카드뉴스가 **무엇을 중심으로** 만들어져야 하는지 정하는 단계다. 정한 내용은 사용자 확인을 받은 뒤 research-topic → plan-cardnews로 넘어간다. **사실을 조사하거나 문구를 쓰는 단계가 아니다.** 본격적인 자료 조사는 research-topic이 한다.

기준 문서: [`.claude/commands/cardnews.md`](../../commands/cardnews.md) (전체 순서), [`research-topic`](../research-topic/SKILL.md) (태그·유형 규칙)

## 입력

| 항목 | 필수 | 예시 |
| --- | --- | --- |
| 이미지 | ✅ | 사용자가 준 파일 경로 1장 이상 (`.png .jpg .jpeg .webp`) |
| 유형 희망 | 선택 | 캐릭터 소개 / 굿즈 소개 / 팝업스토어 일정 / 콜라보 내용 |
| 프로젝트 폴더 | 선택 | 주지 않으면 확인 후 `projects/YYYY-MM-DD_<확인된 주제>/`로 만든다 |
| 카드 이미지로 쓸지 | 선택 | 입력 사진을 card-01 이미지로도 쓸지. 쓰면 3단계 cutout-image가 처리한다 |

- 이미지가 없으면 진행하지 말고 요청한다. 웹에서 이미지를 찾아 대신 쓰지 않는다.
- 원본 파일은 **고치거나 옮기거나 지우지 않는다.**

## 출력

| 산출물 | 규격 |
| --- | --- |
| 분석 결과 | `projects/<폴더>/image-analysis.md` — `상태: 확인 대기` → 사용자 확인 후 `상태: 확인됨` |
| 입력 사진 사본 | `projects/<폴더>/input/<원래 파일 이름>` (`cp -n`, 해시 확인). `projects/*/input/`은 `.gitignore`로 제외된다 |

## 정보 구분 (태그)

research-topic의 태그(`[공식]`, `[2차 출처]`, `[팬 해석]`, `[소문]`)에 아래 두 개를 더해 쓴다.

| 구분 | 태그 | 예 | 카드에 쓰는가 |
| --- | --- | --- | --- |
| 이미지에서 확인된 사실 | `[이미지]` | 사진에 "ちいかわ" 로고가 인쇄됨, 인형이 3개 보임, 가격표에 "¥1,650"이라고 적힘 | **직접 쓰지 않는다.** 중심 대상을 정하고 무엇을 조사할지 정하는 근거로만 쓴다 |
| 외부 자료로 검증한 사실 | `[공식]` / `[2차 출처]` | 공식 스토어에 같은 상품이 등록됨 | `[공식]`만 카드에 쓴다 (research-topic 규칙) |
| 추정 정보 | `[추정]` | "생김새로 보아 하치와레로 보임", "2024년 상품으로 보임" | **쓰지 않는다.** "확인 필요"로만 관리하고, 검증되면 태그를 바꾼다 |

- 사진 속 **가격표·날짜·장소 문구**는 `[이미지]`로 **보이는 그대로만** 기록한다. 매장 가격이거나 지난 행사일 수 있으므로 사실로 쓰지 않는다. 카드에는 공식 출처로 확인된 값만 들어간다.

## 도구

| 용도 | 도구 |
| --- | --- |
| 파일 확인 | cutout-image의 "이미지 검사 명령"과 같은 명령 (형식·크기), `md5sum` |
| 이미지 보기 | Read 도구. Read가 읽지 못하는 형식(확장자와 실제 형식이 다른 WebP 등)은 세션 임시 폴더에 PNG 보기용 사본을 만들어 본다 (프로젝트 폴더에 저장하지 않음) |
| 식별 확인 검색 | WebSearch / WebFetch — **식별(이름이 맞는지) 확인에만** 쓴다 |

```
py -X utf8 -c "import sys,json; from PIL import Image; p=sys.argv[1]; im=Image.open(p); print(json.dumps({'file':p,'format':im.format,'width':im.size[0],'height':im.size[1],'mode':im.mode},ensure_ascii=False))" <이미지>
```

## 절차

각 단계가 실패하면 멈추고 보고한다. **8단계(사용자 확인) 전에는 다음 단계(research-topic)로 넘어가지 않는다.**

1. **파일 확인**: 파일이 있는지, 위 명령으로 실제 형식·크기를 보고 `md5sum`을 기록한다. 확장자와 실제 형식이 다르면 적는다.
2. **이미지 보기**: 이미지를 직접 본다. 여러 장이면 모두 본다. 작은 글자가 안 보이면 해당 부분을 확대한 보기용 사본을 임시 폴더에 만들어 본다.
3. **요소 기록 (`[이미지]`)**: 보이는 것을 `I1, I2 …` 번호로 적는다. 해석하지 말고 **보이는 그대로** 쓴다.
   - 텍스트(OCR): 원문 그대로 + 한국어 뜻. 읽기 어려운 글자는 `?`로 둔다
   - 캐릭터: 생김새 특징 (색, 귀 모양, 들고 있는 물건)
   - 상품: 종류(인형·키링·문구 등), 패키지·태그 문구, 로고, 수량
   - 장소·행사: 포스터·간판의 행사명, 기간, 장소 문구
   - **사람 얼굴, 영수증·주문서의 개인정보, 차량 번호 등은 기록하지 않는다.**
4. **식별 후보**: 캐릭터·상품·행사마다 이름 후보, 근거(I번호), 확신도를 적는다.
   - 높음: 로고·패키지 표기 같은 직접 근거가 있거나, 생김새가 분명함
   - 중간: 생김새가 맞지만 직접 근거가 없음
   - 낮음: 비슷한 후보가 여럿이거나 근거가 약함 → 이름을 단정하지 않고 `[추정]`으로 둔다
5. **식별 확인 검색**: 후보 이름이 실제로 존재하고 사진과 맞는지만 확인한다 (공식 사이트·공식 SNS 우선, 없으면 위키). 결과를 "식별 확인 출처" 표에 URL·확인일과 함께 남긴다.
   - 검색 결과로 확인되면 확신도를 올릴 수 있다. 맞지 않으면 낮추거나 후보에서 뺀다.
   - 이 단계에서 가격·일정·설정 같은 **내용 조사는 하지 않는다** (research-topic 담당).
   - 공식 상품인지 확인되지 않은 굿즈는 "공식 상품"이라고 쓰지 않는다.
6. **중심 대상과 유형 정하기 (제안)**: 아래 기준으로 **카드뉴스가 무엇을 다뤄야 하는지** 정한다.

   | 사진 종류 | 제안 유형 | 중심 대상 |
   | --- | --- | --- |
   | 굿즈·상품 사진 | 굿즈 소개 | **사진 속 그 상품** (상품명·시리즈). 캐릭터 일반 소개가 아님 |
   | 팝업·행사 포스터 | 팝업스토어 일정 | **포스터 속 그 행사** |
   | 콜라보 포스터·상품 | 콜라보 내용 | **그 콜라보** (상대 브랜드·작품과 내용) |
   | 캐릭터 그림·공식 일러스트 | 캐릭터 소개 | **사진에 나온 캐릭터(들)** |

   - **중심 키워드**: 중심 대상을 가리키는 이름·상품명·행사명을 3 ~ 6개 적는다. 이후 단계의 "이미지 관련성 검사" 기준이 된다.
   - **조사할 것**: research-topic이 공식 출처에서 찾아야 할 질문을 유형별 필수 항목에 맞춰 적는다 (예: 굿즈면 정식 상품명·출시일·가격·판매처).
   - **캐릭터 폴더**: `assets/characters/<이름>/`가 있는지 확인한다. 없으면 만들지 말고 사용자에게 묻는다 (validate가 이 폴더를 요구함).
7. **기록**: 아래 형식으로 `image-analysis.md`를 쓴다 (`상태: 확인 대기`). 폴더가 정해지지 않았으면 제안 주제로 `projects/YYYY-MM-DD_<제안 주제>/`를 만들고, 사용자가 주제를 바꾸면 확인 단계에서 폴더 이름을 바꾼다 (이 단계에서는 폴더에 다른 파일이 없다). 입력 사진은 `input/`에 `cp -n`으로 복사하고 해시를 확인한다.
8. **사용자 확인 (멈춤)**: 확인된 요소, 식별 결과(확신도), 추정 정보, 제안(주제·유형·중심 대상·캐릭터 폴더·카드 이미지 사용 여부)을 보여 주고 **멈춘다.**
   - 사용자가 확인하면 `상태: 확인됨`으로 바꾸고, 고친 내용(이름·유형·중심 대상)을 반영한다.
   - 확신도 낮음 항목을 사용자가 알려 주면 "사용자 확인"으로 적는다. 사용자 확인은 식별 근거일 뿐, 카드에 쓸 사실(`[공식]`)은 아니다.
   - 확인 전에는 research-topic을 시작하지 않는다.

## 규칙

- [ ] **사용자 확인 전에는 research-topic으로 넘어가지 않는다.**
- [ ] 보이는 것(`[이미지]`), 검증한 것(`[공식]`/`[2차 출처]`), 추정(`[추정]`)을 섞지 않는다.
- [ ] `[이미지]`·`[추정]`은 카드에 직접 쓰지 않는다. 카드에는 research-topic이 공식 출처로 확인한 `[공식]` 항목만 들어간다.
- [ ] 가격·출시일·행사 일정·장소는 사진에 보여도 사실로 쓰지 않는다. 공식 출처가 없으면 임의로 만들지 않는다.
- [ ] 확신도가 낮은 식별은 단정하지 않는다. 공식 상품인지 모르면 "공식"이라고 쓰지 않는다.
- [ ] 중심 대상은 **사진에 실제로 있는 것**으로 정한다. 사진과 관계없는 일반 주제(예: 굿즈 사진인데 "캐릭터 소개")로 바꾸지 않는다. 사용자가 원하면 확인 단계에서 바꾼다.
- [ ] 사람 얼굴·개인정보는 분석하거나 기록하지 않는다.
- [ ] 원본 이미지를 고치거나 옮기지 않는다. 보기용 사본은 임시 폴더에만 만든다.
- [ ] 캐릭터 폴더를 임의로 만들지 않는다.
- [ ] 입력 사진을 카드 이미지로 쓰는지는 사용자가 정한다. 쓰는 경우 cutout-image가 sources.md에 "사용자 제공 사진"과 사용 허가를 기록하고, 파일 이름 앞에 `user-`를 붙여 Git에서 제외한다.
- [ ] 입력 사진은 `projects/<폴더>/input/`과 세션 임시 폴더 말고 다른 곳에 복사하지 않는다 (둘 다 Git에 올라가지 않음).
