# research-topic: 주제 분석 → brief.md

카드뉴스에 들어갈 **사실 재료**를 모으는 단계다. 여기서 정리한 내용만 다음 단계(plan-cardnews, write-copy)에서 쓸 수 있다. 문구를 예쁘게 다듬는 단계가 아니다.

## 입력

| 항목 | 필수 | 예시 |
| --- | --- | --- |
| 주제 | ✅ | 치이카와 캐릭터 소개 |
| 캐릭터 | ✅ | chiikawa (`assets/characters/` 폴더 이름) |
| 유형 | ✅ | 캐릭터 소개 / 굿즈 소개 / 팝업스토어 일정 / 콜라보 내용 중 하나 |
| 참고 자료 | ✅ | 링크(공식 홈페이지, 공식 SNS, 위키, 기사) 또는 붙여넣은 텍스트 |
| image-analysis.md | 이미지 입력일 때 ✅ | analyze-image 결과. **`상태: 확인됨`** 이어야 한다 |

- 하나라도 없으면 진행하지 말고 사용자에게 물어본다.
- 유형을 주지 않았으면 주제를 보고 하나를 제안하고 확인받는다.

### 이미지 입력일 때

- 주제·캐릭터·유형은 image-analysis.md의 **확인값**을 쓴다. `상태: 확인 대기`면 진행하지 말고 analyze-image 확인부터 받으라고 안내한다.
- 참고 자료는 사용자가 준 자료와 image-analysis.md의 "식별 확인 출처"에서 시작한다. 부족하면 **"조사할 것"의 질문에 답하는 공식 출처를 웹에서 찾아도 된다** (공식 홈페이지·공식 스토어·공식 SNS 우선). 찾은 자료는 주제 입력과 같은 방식으로 `references/`에 저장한다.
- **핵심 내용은 중심 대상에 관한 것만** 넣는다. 각 항목 끝에 연결된 중심 키워드나 I번호를 `(이미지: …)`로 적는다. 중심 대상과 관계없는 일반 정보(작품 소개, 다른 캐릭터 설정 등)는 "캐릭터 기본 정보"에 2줄 이내로만 둔다.
- image-analysis.md의 `[이미지]` 항목은 brief.md "이미지 연결"에 옮겨 적을 수 있지만, 핵심 내용의 사실로 쓰지 않는다. `[추정]` 항목은 "확인 필요"로 옮기고, 공식 출처로 확인되면 `[공식]`으로 바꿔 핵심 내용에 넣는다.
- 중심 대상의 공식 정보를 찾지 못하면 일반 정보로 채우지 말고, 무엇을 못 찾았는지 "확인 필요"에 적고 보고한다.

### 유형별로 모을 내용

| 유형 | 핵심 내용에 넣을 것 | 넣지 않을 것 |
| --- | --- | --- |
| 캐릭터 소개 | 캐릭터 **한 명당 한 항목**. 이름과 그 캐릭터를 알아볼 수 있는 특징(외형·성격·말버릇 중 1~2개)만 짧게. 작품을 처음 보는 사람도 알 수 있는 내용으로 고른다. 예: `우사기: (공식 소개에서 확인한 대표 특징 한 줄)`. 4명 이상 모은다 | 굿즈·행사 정보, 작품 줄거리·서사, 에피소드, 한 캐릭터에 대한 긴 설정 설명 |
| 굿즈 소개 | 상품명, 종류, 출시일·판매 기간, 가격, 판매처(공식 스토어·매장), 상품 특징 | 리셀가·중고 시세, 공식 출처로 확인되지 않은 가격·출시일 |
| 팝업스토어 일정 | 행사명, 기간(시작일·종료일), 장소·주소, 운영 시간, 입장 방식(사전 예약·현장 대기), 대표 굿즈·특전 | 공식 공지로 확인되지 않은 일정, 지난 행사 정보를 현재 일정처럼 쓰는 것 |
| 콜라보 내용 | 콜라보 상대(브랜드·작품), 콜라보 내용(상품·메뉴·이벤트), 기간, 장소·판매처, 참여·구매 방법 | 공식 공지로 확인되지 않은 일정, 이미 끝난 콜라보를 현재 일정처럼 쓰는 것 |

- **카드에 쓸 수 있는 태그**는 유형마다 다르다. 그 밖의 태그는 brief.md에 남겨도 되지만 plan-cardnews·write-copy가 쓰지 않는다.
  - 캐릭터 소개: `[공식]`, `[2차 출처]`(위키백과 등). 공식 출처를 찾지 못해도 위키백과 같은 2차 출처로 brief를 채울 수 있다.
  - 굿즈 소개·팝업스토어 일정·콜라보 내용: `[공식]`만.
- 굿즈 소개·팝업스토어 일정·콜라보 내용의 **날짜·가격·장소·운영 시간**은 공식 홈페이지·공식 SNS 공지에서 확인한 것만 `[공식]`으로 쓴다. **임의로 만들지 않는다.** 공식 출처가 없으면 핵심 내용에 넣지 말고 "확인 필요"에 적는다. 출처 표에 확인일을 꼭 남긴다.
- 팝업스토어 일정·콜라보 내용은 작성일 기준으로 이미 끝난 것이면 "확인 필요"에 적고 사용자에게 알린다.

### 캐릭터 공식 출처

캐릭터 폴더에 `assets/characters/캐릭터명/official.md`가 있으면 거기 적힌 공식 링크를 참고 자료에 항상 함께 넣는다.

| 캐릭터 | 공식 출처 |
| --- | --- |
| chiikawa | 원작자 나가노 X 계정 https://x.com/ngnchiikawa |

- X(트위터) 링크는 로그인 없이 열리지 않는 경우가 많다. 열리지 않으면 지어내지 말고, 사용자에게 **해당 게시물 내용을 복사해 붙여 달라**고 요청한다. 붙여 준 게시물은 `[공식]`으로 쓸 수 있다(출처 표에 게시물 URL과 날짜를 적는다).

## 절차

1. **작업 폴더 만들기**: `projects/YYYY-MM-DD_주제/` (주제는 공백 대신 `-`, 예: `projects/2026-11-03_치이카와-굿즈-소개/`). 같은 이름이 있으면 그 폴더를 쓴다.
2. **참고 자료 저장**: 링크는 내용을 읽어 `references/` 폴더에 출처별 `.md`로 요약 저장한다(파일 맨 위에 URL과 읽은 날짜). 붙여넣은 텍스트는 `references/pasted-01.md`처럼 그대로 저장한다. 열리지 않는 링크는 건너뛰고 brief.md의 "확인 필요"에 적는다.
3. **내용 정리**: 참고 자료에서 주제에 필요한 것만 뽑아 아래 형식으로 `brief.md`를 쓴다.
4. **자체 점검**: 아래 "규칙" 체크리스트를 하나씩 확인하고, 어긴 항목은 고친다.
5. **보고**: 사용자에게 brief.md 위치, 정리한 항목 수, "확인 필요" 항목만 짧게 알린다. 다음 단계(plan-cardnews)는 자동으로 시작하지 않는다.

## brief.md 형식

```markdown
# [주제]

- 캐릭터: chiikawa
- 유형: 캐릭터 소개
- 작성일: YYYY-MM-DD

## 이미지 연결 (이미지 입력일 때만)
- 입력: image-analysis.md (input/<파일>)
- 중심 대상: 사진 속 ○○ 키링 3종
- 중심 키워드: ○○ 키링, 치이카와, 하치와레
- [이미지] 사진에서 확인된 요소 (I번호) — 카드에 쓰지 않음

## 캐릭터 기본 정보
- [공식] 내용 한 줄 (출처: S1)
- [2차 출처] 내용 한 줄 (출처: S2)

## 핵심 내용
<!-- 캐릭터 소개: 캐릭터 한 명당 한 항목 / 굿즈 소개: 상품별 / 팝업스토어 일정: 일정 → 장소 → 입장 방식 → 굿즈·특전 순 / 콜라보 내용: 상대 → 내용 → 기간 → 참여 방법 순 -->
1. [공식] 내용 (출처: S1)
2. [2차 출처] 내용 (출처: S2)
3. [팬 해석] 내용 (출처: S3)
4. [공식] ⚠️스포일러 내용 (출처: S1)

## 카드에 쓰기 좋은 포인트
- 가장 반응이 좋을 만한 사실 3~5개 (위 항목 번호로 표시)

## 확인 필요
- 출처끼리 내용이 다른 것, 출처가 약한 것, 열리지 않은 링크

## 출처
| ID | 이름 | 구분 | URL | 확인일 |
| --- | --- | --- | --- | --- |
| S1 | 나가노 X 계정 게시물 | 공식 | https://x.com/ngnchiikawa/status/... | YYYY-MM-DD |
| S2 | 나무위키 치이카와 문서 | 비공식 | https://... | YYYY-MM-DD |
```

## 규칙

- [ ] **참고 자료에 없는 내용은 쓰지 않는다.** 내가 알고 있는 지식이라도 참고 자료로 확인되지 않으면 넣지 않고 "확인 필요"에 적는다.
- [ ] **모든 항목 끝에 출처 ID**(S1, S2…)를 붙이고, 출처 표에 URL을 남긴다.
- [ ] **구분 태그**를 반드시 붙인다. 태그는 **"어디서 확인했나"와 "사실인가 해석인가"** 를 함께 보고 하나만 고른다.
  - `[공식]`: 공식 홈페이지, 원작자·공식 SNS, 원작, 공식 인터뷰에서 확인된 **사실**
  - `[2차 출처]`: 위키, 언론 기사 등에서 확인된 **사실** (날짜, 설정 등). 공식 출처가 없다는 이유로 사실을 `[팬 해석]`으로 낮추지 않는다.
  - `[팬 해석]`: 캐릭터 심리, 숨은 의미, 떡밥 추측처럼 **해석이나 추측**인 것 (출처가 어디든 해석이면 이 태그)
  - `[소문]`: 출처가 약하거나 확인되지 않은 이야기 (가능하면 쓰지 않는다)
  - `[이미지]`: 입력 사진에서 **보이는 것** (analyze-image가 기록). 중심 대상을 정하는 근거일 뿐 사실로 쓰지 않는다
  - `[추정]`: 사진에서 추측했지만 검증되지 않은 것. "확인 필요"에만 둔다
- [ ] 줄거리·에피소드는 어떤 유형에도 넣지 않는다. 캐릭터 설정이 최신 연재에서 바뀐 것(예: 급수 변화)이면 `⚠️스포일러`를 붙인다.
- [ ] 출처끼리 내용이 다르면 둘 다 적지 말고 공식 쪽을 쓰고, 차이는 "확인 필요"에 남긴다.
- [ ] 특정 캐릭터·팬덤을 비하하는 내용은 넣지 않는다.
- [ ] 문장은 짧은 사실 단위로 쓴다. 말투(세모귀 톤)는 write-copy 단계에서 입힌다.
- [ ] 카드용 이미지 가공은 이 단계에서 다루지 않는다(cutout-image 담당). 입력 사진 분석은 analyze-image 결과를 읽기만 한다.
- [ ] **이미지 관련성 (이미지 입력일 때)**: 핵심 내용의 절반 이상이 중심 대상에 관한 항목인지, 각 항목에 `(이미지: …)` 연결이 있는지 확인한다. 아니면 고치거나 부족한 정보를 "확인 필요"에 적는다.

## 분량 기준

카드가 5장(표지 1 + 본문 4)이므로 **핵심 내용은 6~10개**면 충분하다 (캐릭터 소개는 캐릭터 4~6명). 너무 적으면(4개 이하) 참고 자료를 더 달라고 요청한다.
