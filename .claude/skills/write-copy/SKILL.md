# write-copy: outline.md → slides.json

카드에 실제로 들어갈 **문구**를 쓰는 단계다. 결과물 `slides.json`은 fill-figma가 그대로 읽어 피그마 템플릿에 넣는다. 규격은 `templates/layers.md` 5장, 줄바꿈은 6장을 따른다.

## 입력

- `projects/날짜_주제/outline.md`: **`상태: 승인됨`** 이어야 한다. 승인 대기면 진행하지 말고 승인부터 받으라고 안내한다.
- `projects/날짜_주제/brief.md`: 사실 확인과 출처용
- `projects/날짜_주제/cutout-check.md`: cutout-image 결과. 카드별 `image` 경로를 여기서 가져온다. 이미지가 필요 없는 구성(card-01 이미지 열이 `-`)이면 없어도 된다.

## 문구 규칙

| 항목 | 규칙 |
| --- | --- |
| 제목 `title` | **16자 이하**(공백 포함), **줄바꿈 금지**. 한 카드의 핵심을 한눈에 |
| 본문 `body` | **80자 이내**(공백 포함, `\n` 제외). 1장 1메시지, 2~3문장. **42자를 넘으면 띄어쓰기 위치에 `\n`**을 넣어 **최대 2줄**, 각 줄 42자 이하 |
| 출처 `source` | **30자 이내**, `출처: `로 시작. 표지(card-01)는 `""`(빈 값 → 레이어 숨김) |
| 이미지 `image` | card-01만 `cutout-check.md`의 **"결과 파일 (slides.json `image`)" 칸 경로를 그대로**. 이미지가 없는 카드와 card-02 ~ card-05는 `""` |

- 글자 수는 **직접 세서** 확인한다. 넘으면 줄여서 다시 쓴다. 자르거나 말줄임표(…)로 끝내지 않는다.
- 제목이 2줄이 되면 본문과 겹치고, Figma는 한글을 글자 단위로 줄바꿈해 단어 중간이 끊긴다(`templates/layers.md` 6장). `\n` 앞뒤에 공백을 남기지 않는다.
- `image`에는 **`sources.md`에 출처가 기록된 이미지만** 쓴다. cutout-image가 만든 경로는 이미 sources.md에 기록되어 있으므로, cutout-check.md의 경로를 고치지 않고 옮겨 쓴다.
- cutout-check.md가 없거나, card-01 결과가 실패·건너뜀·보류이면 card-01 `image`도 `""`로 두고 "누끼 이미지 필요(cutout-image)"라고 알린다. 경로를 지어내지 않는다.
- 굿즈 소개·팝업스토어 일정·콜라보 내용의 **날짜·가격·장소·운영 시간**은 brief.md 표기를 그대로 옮긴다. 줄이려고 숫자나 날짜 형식을 바꾸지 않는다.

## 유형별 문구

outline.md의 `유형`에 맞춰 쓴다. 작품 줄거리·서사는 어떤 유형에도 넣지 않는다.

| 유형 | 본문에 담을 것 |
| --- | --- |
| 캐릭터 소개 | 외형·성격·특징을 짧게. 긴 설정 설명이나 에피소드 줄거리는 쓰지 않는다 |
| 굿즈 소개 | 상품명, 특징, 공식 가격, 판매처 |
| 팝업스토어 일정 | 공식 기간, 장소, 입장·예약 방법 |
| 콜라보 내용 | 콜라보 상대, 내용, 공식 기간, 참여·구매 방법 |

## 세모귀 말투

- 친근하고 가벼운 말투. 친구에게 덕질 얘기하듯 쓴다. 기본은 **해요체**, 제목은 짧은 명사형·감탄형도 좋다.
- 이모지는 카드당 **최대 1개**. 없어도 된다.
- **사실은 brief.md에 있는 것만** 쓴다. 문구를 살리려고 사실을 부풀리거나 새 설정을 만들지 않는다.
- **brief.md에서 `[공식]` 태그가 붙은 항목만** 쓴다. `[2차 출처]`, `[팬 해석]`, `[소문]` 항목은 쓰지 않는다.
- **가격, 판매일, 팝업·콜라보 일정, 장소는 임의로 만들지 않는다.** 공식 출처에 없으면 "미정"이나 추정으로 채우지 말고 문구에서 빼고, 사용자에게 무엇이 없는지 알린다.
- `[공식]` 항목만으로 outline의 카드를 채울 수 없으면 쓰지 말고 멈춰서 어떤 카드의 어떤 정보가 부족한지 알린다.
- **이미지 입력일 때** (outline에 `이미지 연결` 열이 있으면):
  - `[이미지]`(사진에 보이는 것)·`[추정]` 항목은 쓰지 않는다. 사진 속 가격표·날짜도 공식 출처로 확인된 값이 아니면 쓰지 않는다.
  - card-01 제목이나 본문에 **중심 대상 이름**(image-analysis.md의 중심 키워드)을 넣는다.
  - outline의 `이미지 연결`이 있는 카드는 그 중심 대상에 관한 문구로 쓴다. 일반적인 캐릭터·작품 소개로 바꾸지 않는다.
  - copy-check.md에 `이미지 연결` 열을 추가해 카드마다 연결된 중심 키워드를 적는다.
- outline에 `⚠️스포일러`가 있는 카드는 제목이나 본문 앞에 `⚠️스포 주의`를 넣는다.
- 표지(card-01)의 제목과 본문에는 스포일러를 드러내지 않는다.
- 금지: 특정 캐릭터·팬덤 비하, "역대급", "충격", "소름" 같은 낚시성 과장, 다른 작품과의 우열 비교.

### 좋은 예 / 나쁜 예

| | 제목 | 본문 |
| --- | --- | --- |
| 좋은 예 | ○○ 팝업, 언제 열려요? | ○월 ○일부터 ○월 ○일까지 ○○에서 열려요.`\n`입장은 공식 사이트 예약으로 할 수 있어요. (← ○○는 공식 공지 값) |
| 나쁜 예 | 충격! 역대급 팝업 온다 | 아마 다음 달쯤 열릴 것 같고, 가격은 1만 원대로 예상돼요. (← 공식 출처 없는 일정·가격, 과장) |

## 절차

1. outline.md가 승인됨인지 확인한다.
2. 카드별로 outline의 핵심 메시지와 brief 항목을 보고 `title`, `body`를 쓴다.
3. `source`는 해당 brief 항목의 출처 ID를 출처 표에서 찾아 짧게 쓴다. 예: `출처: 공식 홈페이지`, `출처: 나가노 X`
4. `image`는 cutout-check.md의 card-01 "결과 파일" 칸을 읽어 그대로 쓰고, 나머지 카드는 `""`로 둔다 (위 문구 규칙의 `image` 항목).
5. 아래 형식으로 `projects/날짜_주제/slides.json`을 쓴다(UTF-8).
6. `py scripts/fill_figma.py validate projects/날짜_주제/slides.json`으로 검사한다. **통과해야 끝낼 수 있다**(아래 "validate 검사" 참고).
7. **자체 검사**를 하고, 결과를 `projects/날짜_주제/copy-check.md`에 표로 남긴다.
8. 사용자에게 5장의 제목·본문을 표로 보여 주고, 검사 결과(통과/수정한 항목)를 알린다. 수정 요청이 오면 해당 카드만 고친다.

## slides.json 형식

```json
{
  "series": "세모귀",
  "topic": "치이카와 캐릭터 소개",
  "character": "chiikawa",
  "slides": [
    { "frame": "card-01", "title": "...", "body": "...", "source": "", "image": "assets/characters/chiikawa/cutout/chiikawa-20261103-01.png" },
    { "frame": "card-02", "title": "...", "body": "...", "source": "출처: 공식 홈페이지", "image": "" },
    { "frame": "card-03", "title": "...", "body": "...", "source": "출처: 공식 홈페이지", "image": "" },
    { "frame": "card-04", "title": "...", "body": "...", "source": "출처: 공식 홈페이지", "image": "" },
    { "frame": "card-05", "title": "...", "body": "...", "source": "출처: 공식 홈페이지", "image": "" }
  ]
}
```

- `slides`는 정확히 5개, `frame`은 `card-01` ~ `card-05` 순서.
- 다섯 필드(`frame`, `title`, `body`, `source`, `image`)는 빈 값이어도 항상 넣는다.

## validate 검사

- `결과: 실패`면 고친 뒤 다시 실행한다.
- validate는 제목 17~20자와 본문 줄바꿈 문제를 **경고로만** 알리고 `결과: 통과 (경고 있음)`을 낸다. 이 문구 규칙은 경고도 고쳐서 없앤다.
- 사용 허가 여부, 이미지 해상도 경고는 문구로 고칠 수 없으므로 사용자에게 그대로 알린다.
- `png/`에 이미 PNG가 있다는 오류는 문구 문제가 아니다. PNG를 지우지 말고 사용자에게 어떻게 할지 묻는다. 그 전까지는 끝내지 않는다.

## 자체 검사 (copy-check.md)

| 카드 | 제목 글자 수 | 본문 글자 수 | 본문 줄 수 | 출처 글자 수 | brief 근거 | 톤·금지어 | 결과 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| card-01 | 14/16 | 52/80 | 2/2 | 0/30 | - | OK | 통과 |

- 글자 수는 validate 출력으로 확인한다. 눈대중으로 세지 않는다.
- 하나라도 실패하면 고친 뒤 다시 검사한다. 최종 결과가 전부 통과일 때만 끝낸다.
