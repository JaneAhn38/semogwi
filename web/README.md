# 세모귀 웹 (로컬 전용)

웹페이지에서 주제를 입력하면 AI가 자료를 조사하고 카드뉴스 5장의 문구와 디자인을 만들어 PNG로 내보내는 프로그램입니다. 사용자는 구성안과 디자인을 각각 확인·수정·승인합니다.

## 설치와 실행 (팀원용)

### 1. 필요한 프로그램

| 프로그램 | 용도 | 필수 |
| --- | --- | --- |
| Windows + Python 3.11 이상 (`py` 실행기 포함, 개발 환경은 3.13) | 웹 서버 | 필수 |
| 시스템 Python의 `rembg`, `Pillow`, `onnxruntime` + 누끼 모델 파일 | 배경 제거 | 선택 |
| Claude Code CLI (`claude`), Claude 구독 로그인 | 실제 AI 조사·문구 | 선택 (없으면 데모 모드만) |

### 2. 코드 받기

```
git clone https://github.com/JaneAhn38/semogwi.git
cd semogwi
git switch feature/web-app      (main에 병합되기 전)
```

### 3. 웹 서버 실행

`web` 폴더의 `run.bat`을 더블클릭한 뒤 브라우저에서 **http://127.0.0.1:8000** 을 엽니다. 처음 실행하면 `web/.venv` 가상환경을 만들고 `requirements.txt`(FastAPI, uvicorn, python-multipart, pytest, httpx)를 설치합니다. 끄려면 창에서 `Ctrl+C`를 누릅니다.

터미널로 직접 실행:

```
cd web
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

테스트: `.venv\Scripts\python -m pytest tests -q` (Claude를 호출하지 않아 한도가 차감되지 않고, 배경 제거 모델도 쓰지 않습니다)

### 3-1. 팀원과 공유하기 (Cloudflare Tunnel, 선택)

기본(`run.bat`)은 로컬 전용입니다. 이 PC의 브라우저에서 127.0.0.1이나 localhost로 연 접속만 받습니다. 팀원에게 공유하려면 다음처럼 실행합니다.

1. `run.bat` 대신 **`share.bat`** 으로 서버를 켭니다. 창에 `[share] Access code: ...`로 **접속 코드**가 나옵니다. 이 코드는 켤 때마다 새로 만들어집니다.
2. 다른 창에서 `cloudflared tunnel --url http://127.0.0.1:8000`을 실행합니다.
3. 터널 주소(`https://….trycloudflare.com`)와 접속 코드를 팀원에게 **따로** 알려 줍니다. 팀원은 첫 화면에서 코드를 한 번 입력하면 12시간 동안 쓸 수 있습니다.

동작과 안전장치:
- 서버는 계속 127.0.0.1에서만 열리고, 같은 와이파이의 다른 기기에는 열리지 않습니다. 외부 요청은 cloudflared를 거쳐서만 들어옵니다.
- 로컬 접속은 지금과 똑같이 코드 없이 됩니다. 단, Cloudflare 헤더(`cf-ray` 등)가 붙은 요청은 Host가 로컬이어도 외부 요청으로 보고 코드를 확인합니다.
- 공유 모드에서도 허용한 공개 주소(기본 `*.trycloudflare.com`)만 받고, 그 밖의 Host는 지금처럼 403으로 막습니다.
- 접속 코드는 서버만 압니다. 쿠키에는 코드 원문이 아니라 서명만 들어가고, 쿠키는 HttpOnly·Secure·SameSite=Lax입니다. 서버를 다시 켜 코드가 바뀌면 예전 쿠키는 더 이상 통하지 않습니다.
- 코드를 10번 틀리면 10분 동안 로그인을 막습니다. 다른 사이트에서 보낸 요청(Origin 불일치)은 로그인 뒤에도 막습니다.
- 코드를 고정하려면 실행 전에 `set SEMOGWI_ACCESS_CODE=8자이상코드`를 입력합니다. 고정 도메인(named tunnel)을 쓰면 `set SEMOGWI_SHARE_HOSTS=semogwi.example.com`처럼 허용할 주소를 정합니다.
- 공유 중 팀원이 실행한 AI 작업은 **서버를 켠 사람의 Claude 구독 한도**를 씁니다. 모든 작업도 서로 공유됩니다(작업 주소를 알면 열 수 있음). 다 쓰면 cloudflared 창과 서버 창을 닫아 주세요.

### 4. 배경 제거 준비 (선택)

배경 제거는 웹 가상환경이 아니라 **시스템 Python**(`py`)으로 `scripts/cutout.py`를 실행합니다. 웹에서는 모델을 자동으로 내려받지 않으므로 한 번 직접 내려받아 둡니다.

```
py -m pip install "rembg[cpu]" pillow
py scripts\cutout.py 아무사진.jpg 결과.png --model isnet-general-use
py scripts\cutout.py 아무사진.jpg 결과.png --model u2net
py scripts\cutout.py 아무사진.jpg 결과.png --model isnet-anime
```

모델 파일은 `%USERPROFILE%\.rembg` (또는 `.u2net`)에 저장되고 저장소에는 포함하지 않습니다. 모델이 하나도 없으면 화면에 "배경 제거를 쓸 수 없어요"가 뜨고 원본 이미지는 그대로 쓸 수 있습니다. `bria-rmbg`(고품질)는 비상업용 라이선스(CC BY-NC 4.0)라 필요한 경우에만 각자 받으세요.

### 5. 실제 AI 모드 준비 (선택)

[Claude Code](https://docs.claude.com/claude-code)를 설치하고 터미널에서 `claude auth login`으로 본인 구독 계정에 로그인합니다. API 키나 `.env` 파일은 쓰지 않습니다. 설치하지 않으면 데모 모드로만 동작합니다.

### Git에 올리지 않는 것

`web/.venv/`, `web/data/`(업로드 이미지·작업 기록·AI 작업 폴더), `__pycache__/`, `.pytest_cache/`는 `web/.gitignore`로 제외합니다. 업로드한 사진은 각자 PC에만 남습니다.

## 제작 방식

| | 실제 AI | 데모 |
| --- | --- | --- |
| 유형 | "AI가 판단"이면 조사 전에 짧게 판단 (웹 없음) | 주제 키워드로 추정 |
| 조사·문구 | Claude가 웹을 검색해 템플릿 필드를 채움 | 예시 문구, 조사 안 함 |
| 디자인 | 팀이 만든 고정 템플릿 (AI 호출 없음) | 같음 |
| PNG | 표시 없음 | `DEMO SAMPLE` 표시 |
| Pro 한도 | 조사 단계에서 차감 | 차감 없음 |

AI 호출이 실패하면 데모 결과로 대신하지 않고 이유를 표시합니다. 조사 단계는 **다시 시도** 버튼으로, 카드 문구는 다시 요청해서 이어 갈 수 있고 그동안 기존 결과는 유지됩니다.

## 카드 이미지 (구성안 단계)

- 카드의 이미지 자리마다 이미지를 고르거나, 그 자리에서 바로 올려 넣거나 교체할 수 있습니다. 사용 권한을 따로 고르지 않아도 되고(학술 연구·내부 시연용), 출처는 적으면 함께 저장합니다. 권한 기록은 '확인 필요'로 남고 '허가됨'으로 바꿔 기록하지 않습니다.
- 올린 이미지는 빈 자리에 **추천만** 표시합니다. **적용**을 눌러야 카드에 들어갑니다.
- 자리마다 배경 제거 ON/OFF, 원본·누끼 비교, 원본 복원, 크기(30~300%)·위치 조정을 할 수 있고 값은 작업 데이터(`slotImages`)에 저장됩니다.
- 누끼는 투명 여백을 빼고 피사체 기준으로 자리의 90%에 맞춥니다. 이미지가 없는 자리는 PNG에 아무것도 그리지 않습니다(마스코트 자리표시 없음).
- 화면, PNG 파일 이름(`semogwi-card-01.png` ~ `05`), ZIP 안의 순서는 모두 card-01 ~ card-05입니다.

## 유연한 구성안 (card-02 ~ card-05)

- card-01은 표지로 고정하고, card-02 ~ card-05는 AI가 확보된 자료에 맞춰 유형의 본문 템플릿 4종과 **자유 구성**(`templates/<유형>-free.json`) 중에서 고릅니다. 디자인 토큰(색·글꼴·머리글·바닥글)은 같은 유형과 같습니다.
- 자유 구성 카드: 카드 제목 + 소개 문장 + 정보 줄(항목·값) + 참고 사항 + 선택 이미지. 내용 양에 맞춰 상자 높이가 바뀌고, 내용이 적으면 가운데 쪽에 놓습니다 (`stack` 요소, `static/renderer.js`).
- 전용 템플릿의 필수 정보(예: 구매 방법의 판매 시작, 마무리의 발매일)가 없으면 서버가 그 카드를 자유 구성으로 바꾸고 **있는 값만** 정보 줄로 옮깁니다. 필수 칸이 비었다는 이유로 승인이 막히지 않습니다 (표지의 이름 칸은 예외).
- 내용이 없는 카드, 앞 카드 정보를 되풀이한 카드는 AI에게 한 번만 고쳐 쓰게 하고, 그래도 남으면 경고로 알립니다.
- 출처 충돌·미확인 값은 자유 구성 카드 문구 안에 있어도 찾아서 기존처럼 승인을 막습니다.
- 구성안 편집에서 카드마다 **카드 구성**을 바꿀 수 있습니다. 필수 정보가 없는 구성으로는 바꿀 수 없고, 바꾸면 넣어 둔 이미지는 새 이미지 자리로 옮깁니다.
- 예전 작업(형식 3 legacy)은 그대로 고정 구성입니다.

## 고정 템플릿 (4유형 × 5장)

새 작업은 팀이 만든 PNG 디자인 20장을 옮긴 고정 템플릿으로 만듭니다. 유형마다 card-01 ~ card-05의 디자인이 정해져 있고, AI는 디자인을 만들지 않고 각 카드의 필드(이름, 가격, 기간 등)만 씁니다.

- 3단계 구성안에서 카드마다 템플릿 미리보기를 보며 필드와 이미지 자리를 고칩니다. 입력하는 즉시 미리보기가 바뀝니다.
- 디자인 유형은 자동으로 정해지고, 구성안 단계에서 직접 바꿀 수 있습니다.
- 비워 둔 선택 항목은 카드에서 숨깁니다. 자리표시 문구(`[캐릭터 이름]` 등)는 저장할 수 없습니다.
- 이미지 자리가 여러 개인 카드(굿즈 라인업 4개 등)는 자리마다 이미지를 고릅니다.
- 이전 작업(AI 디자인, 표지 + 본문 반복 템플릿)은 만들어진 방식 그대로 열립니다.
- 규격과 비교 결과: `docs/template-spec.md`

### 캐릭터 소개 · 프로필 (character-02, 유동 항목)

- **이름은 필수**이고, 나머지 프로필은 고정 칸(생일·좋아하는 것·작가)이 아니라 **프로필 항목 0~3개**(항목명 6자·내용 16자)입니다. 예: 피카츄라면 도감 번호 / 타입 / 분류.
- AI는 조사 항목(생일·좋아하는 것·제작자·**기타 공식 프로필** `profile_extra`) 중 출처가 확인된 값만 고릅니다. AI가 비워 두면 서버가 근거 있는 조사 값을 그대로 옮겨 채우고, 자르거나 지어내지 않습니다.
- 프로필 항목마다 조사 값과 대조해 조사에 없는 값은 "근거를 확인하지 못한 정보예요" 경고를 띄웁니다. 나무위키만 근거인 값은 프로필에 쓰지 않습니다.
- 항목이 적으면 빈 줄 없이 이미지 크기·줄 간격을 바꾸고, 이름만 있으면 이름을 크게 쓰고 **소개 문장**(50자)을 아래에 둡니다. 이미지가 없으면 글을 상자 가운데에 둡니다. 색·테두리·PROFILE 띠·태그·데뷔 영역은 그대로입니다 (렌더러 `profile` 요소).
- 구성안 편집에서 프로필 항목을 `+ 프로필 항목 추가`·`삭제`로 늘리고 줄이며 항목명과 내용을 고칩니다 (0~3개).
- 예전에 만든 고정 4줄 프로필 카드는 `character-02-v1`로 예전 디자인 그대로 열립니다.

### 캐릭터 소개 · 친구와 TMI (character-04, 가로형)

- 친구 캐릭터마다 **원형 이미지 · 이름 · 관계 · 개별 TMI 상자**를 세로로 묶고, 그 묶음을 가로로 나열합니다. 공통 TMI 칸은 없습니다.
- 친구는 **2~4명**(기본 3명)이고 구성안 편집에서 `+ 친구 추가`·`삭제`로 바꿉니다. 이름 8자, 관계 8자, TMI 60자입니다.
- 인원에 맞춰 크기가 바뀝니다. TMI 글자 크기는 2명 32px, 3명 30px, 4명 28px입니다. 글이 길면 이미지를 먼저 줄이고, 그래도 모자랄 때만 글자를 24px까지 줄입니다. 글자를 자르지 않고, 그래도 넘치면 화면에 경고를 보여 줍니다.
- 친구를 지우거나 추가하면 친구별 이미지가 그 친구를 따라갑니다. 없는 친구의 이미지 자리는 숨기고 추천하지 않습니다. TMI가 없는 친구는 TMI 상자를 그리지 않습니다.
- AI는 확인된 친구만 넣고 관계·TMI도 확인된 것만 씁니다. 확인된 친구가 1명뿐이면 인원을 채우지 않고 자유 구성 카드로 바꿉니다(60자 TMI는 소개 문장으로 옮김).
- 조사는 친구 등 관련 캐릭터를 그룹 이름이 아니라 한 명씩 `이름(관계), 이름(관계)`로 모읍니다. 2명 이상 확인됐는데 AI가 다른 구성을 고르면 서버가 한 번 다시 쓰게 해 card-04를 가로형으로 만듭니다.
- 그룹 이름(예: 떡잎마을 방범대)만 확인되면 구성원을 지어내지 않고 자유 구성으로 두며, 카드에 그 이유와 '카드 구성 → 친구와 TMI'로 직접 입력하는 방법을 안내합니다. '친구와 TMI'는 친구 정보가 없어도 고를 수 있고, 2명 이상 입력하기 전에는 승인할 수 없습니다.
- 예전에 저장한 작업(공통 TMI가 있는 카드)은 `character-04-v1`(이전 형식)으로 그대로 열립니다. 공통 TMI를 특정 친구의 사실로 옮기지 않습니다. 카드 구성에서 새 가로형으로 바꾸면 이름·관계만 옮깁니다.
- 성격과 특징(character-03)의 설명은 60자(4줄)까지 씁니다.

### 캐릭터 소개 · 마무리 (character-05, 다음 캐릭터 예고)

- 참고 디자인: `templates/reference/캐릭터 소개 · 05 마무리 (새 디자인).png`. "다음 캐릭터도 보고 싶다면" 제목, NEXT CHARACTER 카드(이름·힌트·공개일·회차), 다음 편 예고, 팔로우 안내로 구성합니다.
- 다음 편 정보는 조사로 알 수 없는 계획이라 **사용자가 구성안에서 입력**합니다. 구성안 작성·카드 다시 쓰기에서 AI는 이 칸을 쓰지 않고, 다시 써도 사용자가 쓴 값은 그대로 남습니다.
- **다음 캐릭터 이름이 있으면** 예고 카드: 이름·힌트·공개 문구·회차와 다음 캐릭터 이미지(원 안, 사용자가 직접 넣는 자리. 이미지 추천에서 제외). 회차는 입력했을 때만 'No. 7'처럼 보이고 비우면 숨깁니다. 나머지 비운 칸은 기본 문구로 보입니다 — 힌트 '어떤 친구일지 기대해 주세요', 공개 '다음 게시물에서 만나요!', 예고 '다음 편에서 또 다른 귀여운 친구를 소개할게요'.
- **이름이 비어 있으면** 독자 참여 카드: 제목 '다음엔 어떤 친구를 만나볼까요?', '보고 싶은 캐릭터를 댓글로 알려주세요!', 어두운 상자는 '같이 골라요'. 회차와 다음 편 칸은 숨깁니다 (값은 지우지 않고 보관). 템플릿 조건 `"if": "!next_name"`(값이 비어 있을 때)으로 전환합니다.
- **힌트·공개 문구 AI로 쓰기**(구성안 card-05 편집): 누를 때만 AI를 1회 부릅니다(검색 없음, 저장된 조사 자료와 붙여 넣은 자료만). 힌트는 공식 출처나 사용자 자료가 근거이고 그 자료에 다음 캐릭터 이름이 있을 때만 쓰고, 아니면 기본 문구를 넣습니다. 공개 문구에 날짜·요일·'내일' 같은 시점이 있으면 기본 문구로 바꿉니다. 데모에서는 AI 없이 기본 문구를 넣습니다.
- 조사한 사실을 담지 않는 카드라 출처를 표시하지 않습니다(`showSource: false`).
- 예전 디자인(이런 분께 추천해요)으로 저장한 작업은 `character-05-v1`로 그대로 열립니다. 예전 참고 이미지 `캐릭터 소개 · 05 마무리.png`도 남아 있습니다.
- 템플릿 요소 옵션: 글자 요소의 `fallback`(값이 비면 보여 줄 기본 문구), `prefix`(값 앞에 붙는 글자, 예: 'No. ').

### 조사 항목과 참고 자료

- 입력 화면의 **참고 자료 직접 입력**에 공식 공지·판매 페이지에서 확인한 내용을 붙여 넣으면, AI가 조사할 때 함께 읽고 카드에는 **사용자 제공** 자료로 표시합니다. 데모에서는 저장만 합니다.
- 참고 자료에는 **출처 종류**(공식 출처 / 나무위키 / 기타)와 옮겨 온 **주소**를 함께 적을 수 있습니다. '공식 출처'를 골라도 공식 확인으로 처리하지 않습니다.
- **출처 기준 (2026-11-23):** 세모귀는 개인 캡스톤 발표·시연용 프로젝트라 공식 출처를 **우선 참고하되 필수 조건으로 두지 않습니다.** 기사·위키·나무위키·팬덤 정보 등 2차 자료와, 값이 그대로 적힌 검색 결과(원문 미확인으로 따로 기록)도 4가지 유형 모두에서 근거로 씁니다. 출처 URL·출처 종류(공식/2차/나무위키/사용자 제공/상세 이미지)·원문 게시일·조사일은 계속 기록하고 조사 결과에 표시합니다. 공식 확인 여부만으로는 자료 부족으로 보거나 승인을 막지 않습니다.
- **나무위키는 모든 유형의 2차 자료**입니다. 다만 **자동으로 읽는 것은 캐릭터 소개만**이고(굿즈·팝업·콜라보 조사에서는 `WebFetch` 차단 유지), 다른 유형은 사용자가 직접 준 나무위키 자료를 씁니다. 공식 자료와 값이 다르면 출처 충돌로 알립니다. 미러 사이트는 근거로 쓰지 않습니다. 자세한 기준: `docs/site-access-policy.md`
- 실제 AI 조사는 유형별 항목(캐릭터: 이름·첫 등장·성격…, 팝업: 기간·운영 시간·장소·휴무일…)을 하나씩 찾고, 2단계 **자료 조사 결과**에 항목마다 상태(공식 확인, 2차 자료, 사용자 제공, 출처 충돌, 정보 확인 필요 등), 근거 문장, 출처 링크를 보여 줍니다.
- 찾지 못한 항목은 지어내지 않고 **정보 확인 필요**로 남깁니다. **카드에서 입력**을 누르면 그 항목을 쓰는 카드 편집으로 이동합니다. 구성안의 필드마다 같은 상태 배지가 붙습니다.
- 같은 항목에 출처마다 다른 값이 나오면 **출처 충돌**로 값을 모두 보여 주고, 가격·일정·장소 같은 항목은 사용자가 확인해 고칠 때까지 승인을 막습니다.
- 검색 실패, 접속 실패, 자동 접근 금지 사이트는 **조사 중 문제**에 이유별로 표시합니다.

화면을 새로 고쳤는데 예전 화면이 보이면 Ctrl+F5로 새로 고침해 주세요. 지금은 화면 파일을 매번 확인하도록 서버가 알려 주므로 다시 생기지 않습니다.

## 상세페이지 이미지 자료 (이미지형 상세페이지)

쇼핑몰 상세 설명이 글이 아니라 이미지면 자동 조사(WebFetch)는 HTML 글자만 읽어서 상품 정보를 놓칩니다. 그래서 상세 이미지를 따로 받아 AI 비전으로 읽습니다.

- **직접 올리기:** 1단계나 2단계 자료 입력 화면의 "상세페이지 이미지"에 스크린샷·이미지 파일을 올립니다 (작업당 10장). 카드에 넣는 이미지와 따로 보관하며 카드 이미지 추천에도 섞이지 않습니다.
- **참고 URL에서 찾기:** 버튼을 누를 때만 그 페이지 한 곳에 요청합니다. 자동 수집 금지 사이트(`app/site_policy.json`), 대기 중인 사이트, robots.txt가 막은 주소(이미지 호스트 포함), 로컬·사설망 주소에는 요청하지 않습니다. 요청을 막는 응답(403·429 등)을 받으면 멈추고 사이트 단위 대기에 기록합니다. 자바스크립트로 그리는 상세 영역은 찾지 못할 수 있어 스크린샷을 안내합니다.
- **판독:** 긴 이미지는 시스템 Python의 Pillow로 폭 1000px·높이 1400px 조각으로 나눠(`app/image_tiles.py`) `claude -p --input-format stream-json`에 이미지로 보냅니다. 파일 읽기·웹 도구를 주지 않습니다. 한 번에 최대 24조각.
- **읽은 값 검사:** 값마다 출처 이미지(근거 id `img1` …)와 조각 번호, 이미지 속 문장을 남깁니다. AI가 `unclear`로 답했거나 값의 숫자가 이미지 문장에 없으면 **확인 필요**로 바꾸고, 짐작한 글자는 저장하지 않습니다.
- **통합:** 이미지에서 읽은 값은 조사 항목 상태 **상세 이미지**로 표시합니다. 페이지(HTML)나 다른 이미지와 값이 다르면 **출처 충돌**로 남기고 자동으로 고르지 않습니다 (공식 자료만 허용하는 항목은 사용자가 고칠 때까지 승인 불가). 같은 이미지에서 같은 항목을 여러 줄 읽은 것은 한 값으로 합칩니다.
- **핵심 정보만으로 진행:** 유형별 핵심 항목(굿즈: 상품명 + 가격·특징·구성품 중 하나 등, `app/research.py`의 `CORE`)이 확인되면 선택 정보가 없어도 구성안을 만듭니다. 근거가 없는 칸은 비워 두고, 템플릿 필수 칸이 비면 구성안 승인 단계에서 직접 입력합니다.
- 구성안 필드마다 **상세 이미지 / 사용자 제공 / 공식 확인 / 정보 확인 필요** 배지가 붙고, 승인 전에 고칠 수 있습니다.
- 한도: 판독 1회 + 구성안 1회 (실측 약 20~30초).

## 자료조사 파이프라인 (조사 → 저장 → 구성안)

새 작업은 **자료 조사**와 **구성안 작성**을 따로 실행합니다. 조사 결과를 먼저 작업에 저장한 뒤, 저장된 사실·출처만으로 구성안을 씁니다(웹 도구 없음). 구성안 작성이 실패해도 조사 결과는 남고, '다시 시도'는 조사를 반복하지 않고 구성안만 씁니다.

- 조사 항목은 유형마다 하나의 표(`app/research.py`의 `SPECS`)로 정의합니다: 공식 출처 우선 여부(`official`, 필수 아님), 중요도(핵심·중요·일반), 여러 개 나열 여부, 변경 가능성, 조사 안내.
- 비어 있는 항목은 이유를 구분해 보여 줍니다: **자료 없음**(찾아봤지만 없음) · **검색·읽기 실패** · **접근 제한**(금지·대기·거절) · **미조사**. 예전 조사 기록은 '정보 확인 필요'로 그대로 열립니다.
- 여러 개가 나열되는 항목은 일부만 조사됐거나 전체 규모를 알 수 없으면 **검토 필요**로 표시합니다(개수를 강제하지 않음).
- 정보마다 출처 주소, 페이지를 실제로 읽었는지, 근거 문장, 조사 시각을 기록합니다. 근거 문장이 페이지에 실제로 있는지는 아직 검증하지 않으며 '근거 문장 미검증'으로 표시합니다.
- 비교: `.venv\Scripts\python tools\compare_research.py <작업 id 또는 보관함 버전 id> <다른 하나>`
- 구조와 다음 단계(다국어 검색어, 누락 항목 재조사, 항목별 추가 조사) 설계: `docs/research-pipeline.md`

## 조사 자료 보관함 (저장된 자료 사용 / 새로 조사하기)

같은 주제로 여러 번 만들 때 조사 결과가 매번 달라지지 않도록, AI 조사 결과(사실·출처·조사 항목)를 버전으로 저장해 다시 씁니다. 카드 문구와 디자인은 저장하지 않아 매번 새로 쓸 수 있습니다.

- **저장 위치:** `web/data/research/<버전 id>.json`(작업 파일과 같은 JSON 방식, 데이터베이스 없음, Git에 올리지 않음). 콘텐츠 유형과 주제(공백·대소문자 무시)가 같으면 같은 주제입니다.
- **시작 화면:** 실제 AI 모드에서 주제를 입력하면 '자료 조사 방식'이 나옵니다.
  - **저장된 자료 사용:** 버전(번호 · 조사일 · 읽은 출처 수)을 고르고 '자료 보기'로 항목·친구·출처를 확인합니다. 새 웹 조사 없이 그 자료로 구성안 문구만 새로 씁니다(AI 1회). 시작 화면의 '참고 자료 직접 입력'은 사용자 제공 자료로 더해지고, 저장된 자료는 바뀌지 않습니다.
  - **새로 조사하기:** AI가 새로 조사하고 결과를 새 버전으로 추가합니다. 예전 버전은 덮어쓰지 않습니다.
  - 저장된 자료가 없으면 새로 조사하도록 안내합니다.
- **최신성:** 버전마다 조사일과 출처를 기록합니다. 굿즈·팝업스토어·콜라보 자료는 쓸 때 "조사일 … 가격·일정이 바뀌었을 수 있어요"라고 알립니다.
- **조사 결과 화면:** 어느 버전을 썼는지, 또는 새 버전으로 저장했는지 보여 줍니다.
- **API:** `GET /api/research-library?topic=&contentType=`(버전 목록), `GET /api/research-library/{id}`(버전 내용).

### 조사 결과 화면의 추가 조사

조사 결과가 나온 뒤 부족한 내용이 있으면 2단계 '자료 조사 결과'의 **추가 조사**에 찾을 내용을 적습니다 (실제 AI 모드, 구성안 승인 전: `waiting_outline`·`waiting_research`).

- **조사:** 지금 자료를 맥락으로 주고 적은 내용만 웹 조사 1회로 찾습니다(`ai_provider.more_research`). 출처 검증·자동 접근 금지·요청 대기 규칙은 첫 조사와 같습니다. 캐릭터 소개는 TMI가 없는 친구가 있을 때만 캐릭터별 조사를 더 합니다.
- **초안:** 결과는 `job.researchDraft`에만 둡니다. 통합하기 전에는 조사 자료(`job.research`)와 구성안이 바뀌지 않습니다. 이번 회차에 새로 찾은 항목·늘어난 항목·다른 값·출처·사실·캐릭터에는 회차 번호(`moreRound`/`round`)를 붙여 기존 자료와 구분해 보여 줍니다.
- **다른 값:** 기존 값을 덮어쓰지 않고 '다른 값'으로 붙입니다. 쓸 값을 고르기 전에는 통합할 수 없고, 고르지 않은 값은 `dismissed`에 남습니다.
- **통합:** 구성안 단계면 통합한 자료를 새 조사 버전으로 저장합니다(이전 버전은 그대로, `researchVersion.source = "more"`). 구성안은 바꾸지 않고 경고·검증만 다시 계산하며, '전체 구성안 다시 만들기'로 통합 자료를 반영하도록 안내합니다. 통합 자료 검토 단계면 검토 자료에 합치고 '이 자료로 구성안 만들기'를 누를 때 한 번만 새 버전으로 저장합니다. 통합 기록은 `research.moreResearch`에 남습니다.
- **버리기·실패·재시작:** 버리면 초안만 지웁니다. 추가 조사가 실패하거나 서버가 다시 시작되면 오류만 표시하고 자료와 구성안은 그대로입니다. AI 작업 중이거나 확인하지 않은 초안이 있으면 새 추가 조사와 구성안 승인을 받지 않습니다. 조사하는 동안 자료가 바뀌었으면 결과를 쓰지 않습니다.
- **API:** `POST /api/jobs/{id}/research/more`(`{request}`), `POST …/research/more/items/{key}/choose`(`{index}`), `POST …/research/more/accept`, `POST …/research/more/discard`.

### 캐릭터 소개 조사 기준 (친구 카드)

### card-04 크루 고르기 (2026-11-23, 화면 표현은 2026-11-24에 '친구' → '크루')

- 화면에는 **크루**로 보입니다. 카드 제목은 "**○○ 크루 & TMI**"이고 ○○은 표지(card-01)의 캐릭터 이름입니다(`inherit: ["character_name"]`, 예전 형식 character-04-v1도 같음). 표지 이름을 고치면 제목도 바뀌고, 이름이 비어 있으면 "크루 & TMI"로 그립니다. 이름이 길면(표지 최대 12자) 제목 글씨가 줄어듭니다.
- 코드의 키·API·상태 이름(`friends`, `friend_image_N`, `waiting_friends`, `/friends/...`)과 AI 지시문·조사 항목 이름("친구 캐릭터")은 그대로입니다. 단, 템플릿의 카드·칸 이름("크루와 TMI", "크루")은 AI 지시문에도 함께 들어갑니다.
- 'AI 카드뉴스 제작 시작' → 조사가 끝나면 AI가 크루 후보를 최대 4명 추천하고 **크루 고르기**(`waiting_friends`)에서 멈춥니다. 저장된 자료로 시작하면 검토(`waiting_research`) → 크루 고르기 순서입니다.
- 후보: 귀여운 캐릭터·귀여움으로 인기 있는 캐릭터 우선, 사람 캐릭터는 뒤로. 후보마다 이유 한 줄과 출처가 붙습니다(이유는 카드 문구에 쓰지 않음). 읽은 자료에 이름이 나오고 읽은 페이지(나무위키 포함 현재 출처 규칙)가 근거인 후보만 받습니다. 추천이 실패하거나 모자라면 조사 자료에 나온 캐릭터로 채우고 안내합니다. 후보는 조사 자료(`friendCandidates`)에도 남아 '저장된 자료 사용' 때 다시 추천하지 않습니다.
- **후보 미리보기 (2026-11-24, `app/friend_preview.py`)**: 캐릭터를 모르는 사용자도 고를 수 있게 후보마다 작은 사진이나 확인할 페이지 링크를 붙입니다.
  - 사진은 **공식 출처 중 실제로 읽은, 그 후보 전용 페이지**(제목·주소에 후보 이름이 있음)에서만 찾습니다. 서버가 그 페이지 HTML만 한 번 받아(자동 접근 금지 사이트·대기 중 사이트·robots.txt 규칙 그대로) 대표 이미지(`og:image`), 없으면 `alt`가 후보 이름인 이미지의 **주소만** 고르고, 받은 HTML에 후보 이름이 없으면 쓰지 않습니다. 목록 페이지·중심 캐릭터 페이지의 이미지는 후보가 아닐 수 있어 쓰지 않습니다.
  - 조사 자료에 전용 페이지가 없는 후보는 추천 직후 AI가 **공식 프로필 페이지를 한 번 더 찾습니다**(WebSearch·WebFetch, AI 1회, 실제 AI만). 도구 기록으로 실제로 읽은 공식 페이지만 받습니다. 후보는 먼저 보여 주고 사진은 뒤이어 채웁니다("미리보기 찾는 중"). '후보 다시 추천'은 같은 작업 안에서 찾습니다.
  - 이미지 파일은 서버가 받거나 저장하지 않습니다. 브라우저가 원래 주소로 띄우고(referrer 없음, 보일 때만 불러옴) 카드·PNG·사진 칸에는 넣지 않습니다. 작업과 조사 자료에는 주소만 남습니다(`preview`, `link`, `profileSource`).
  - 사진이 없거나 못 불러오면 **사진 보기** 버튼이 나옵니다. "후보 이름 + 작품명"(예: `맹구 짱구는 못말려`)으로 **네이버 이미지 검색**을 새 탭으로 엽니다. 작품명은 조사 항목 '작품·시리즈명'에서 괄호 속 원제와 『』를 뺀 이름이고, 없으면 주제를 씁니다. 검색 주소는 화면에서 만들어 예전 후보에도 나오며, 서버는 검색 사이트에 요청하지 않고 이미지를 가져오거나 저장하지 않습니다. 검색 결과라 다른 캐릭터나 팬아트가 섞일 수 있습니다. 나무위키 등 2차 자료의 이미지는 미리보기로 쓰지 않습니다.
  - 데모는 외부 요청 없이 이름 첫 글자 자리표시와 "미리보기 없음 (데모)", 이름만으로 검색하는 **사진 보기**를 보여 줍니다.
  - 조사는 친구를 최대 4명까지 모으고(카드 최대 인원, 사용량 절약) 후보 추천도 최대 4명입니다. 읽은 페이지가 근거인 캐릭터만 후보가 되므로 자료에 따라 더 적을 수 있습니다.
- **친구 이름 (2026-11-24)**: 조사 항목의 '이름(설명), 이름(설명)'은 괄호 밖 쉼표에서만 나눕니다(`research._split_people`). 괄호 안은 이름이 아니라 설명이고, 관계 말로 끝나는 부분(예: 유치원 친구)은 관계, 나머지(예: 일본판 이름 마사오)는 다른 이름(`aliases`)으로 둡니다. 예: `훈이(마사오, 유치원 친구)` → 이름 훈이, 관계 유치원 친구, 다른 이름 마사오.
  - 이름은 한국에서 쓰는 이름으로 통일합니다(예: 마사오→훈이, 네네→유리, 보오→맹구). 1차 조사·캐릭터별 조사·후보 추천·프로필 검색 지시문에 같은 규칙(`ai_rules.KOREAN_NAME_RULE`)이 있고, 한국 이름은 읽은 자료에서 확인한 것을 우선하며 모르면 원래 이름을 씁니다.
  - 캐릭터별 조사가 다른 이름(마사오, `철수(토오루)` 등)으로 답해도 서버가 조사 목록의 한국 이름에 붙입니다(`research.resolve_name`). 가타카나(マサオ)를 한글로 자동 변환하지는 않습니다.
  - 외부 공유 모드에서는 팀원 브라우저도 그 사이트에 직접 이미지를 요청합니다. 이미지 핫링크를 금지한 사이트를 알게 되면 `site_policy.json`에 등록해 주세요.
- 사용자는 크루원 2~4명을 고릅니다(이름 8자 이내, 목록에 없는 캐릭터도 직접 입력). 고른 순서 = 카드 순서 = 사진 칸 번호입니다. '후보 다시 추천'은 누를 때만 AI를 부릅니다(`POST /api/jobs/{id}/friends/recommend`, 추천 1회 + 프로필 검색 1회).
- 고르면(`POST /api/jobs/{id}/friends/pick`) 고른 크루 중 TMI가 아직 없는 캐릭터만 공식 출처 우선으로 조사하고(새 캐릭터는 찾지 않음), 그 자료를 새 조사 버전으로 저장한 뒤 구성안을 씁니다. 이름·순서·인원은 서버가 정하고 AI는 관계 문구만 쓰며, TMI는 조사로 확인한 것만 넣고 없으면 비웁니다("출처에서 TMI를 확인하지 못한 캐릭터" 안내).
- 구성안 단계의 '**크루 다시 고르기**'(같은 API)는 새로 고른 크루를 조사하고 card-04만 다시 씁니다. 빠진 캐릭터 이름은 이후 문구에 나오면 막습니다. 고른 크루와 중심 캐릭터 말고 다른 캐릭터 이름이 card-04 문구에 들어가면 승인을 막습니다. 편집에서 직접 넣은 캐릭터가 있으면 '**새로 넣은 크루 조사하기**'가 나옵니다(실제 AI).
- 데모는 조사 없이 예시 후보 4명과 고르기 화면을 보여 줍니다. 구성안이 이미 있는 예전 작업은 지금 크루를 고른 것으로 봅니다. 예전 가족 카드는 "크루를 골라 주세요" 오류로 안내합니다.

### 캐릭터별 추가 조사 (친구 TMI)

1차 조사는 중심 캐릭터 위주라 친구 각각의 정보가 비기 쉽습니다. 그래서 캐릭터 소개는 1차 조사 뒤에 **캐릭터별 조사**를 이어서 합니다.

- **1회차:** 1차에서 확인된 친구 캐릭터 각각의 TMI(성격·취미·버릇·작품 속 설정)를 등장인물 목록 페이지 위주로 찾습니다. 친구가 4명 미만이면 4명까지 더 찾습니다(출처에 개별 이름이 나온 캐릭터만, 그룹 이름 제외).
- **2회차:** 1회차에서 TMI를 못 찾은 캐릭터만 이름별로 따로 검색합니다. 그 이상은 하지 않습니다.
- **검사:** 실제로 읽은 페이지가 근거인 TMI만 받습니다. 관계·소속만 되풀이한 문장(예: '방범대 멤버예요'), 다른 캐릭터와 같은 문장, 60자 초과는 쓰지 않고 이유를 남깁니다. 끝내 찾지 못한 캐릭터는 비워 두고 구성안에서 직접 입력하도록 안내합니다.
- **저장·전달:** 캐릭터마다 이름·관계·TMI·근거 문장·출처를 `research.peopleResearch`에 저장하고 보관함에도 함께 남깁니다. 구성안(새로 조사·저장된 자료 사용 모두)의 친구 카드에는 그 캐릭터의 조사된 TMI가 들어갑니다. 사용자가 고친 카드는 바꾸지 않습니다.
- **화면:** 자료 조사 결과의 '캐릭터별 조사 결과'에서 캐릭터별 TMI, 근거 문장, 출처 링크, 추가 조사 검색어·읽은 페이지 수, 쓰지 않은 내용과 이유를 볼 수 있습니다.
- 비용: 캐릭터 소개 '새로 조사하기'는 AI 호출이 1차 조사 1회 + 캐릭터별 조사 1~2회입니다(짱구 실측 약 $0.25~0.45). '저장된 자료 사용'은 구성안 1회입니다.

## 실제 AI 연결

- 이 PC에 로그인된 Claude 구독으로 `claude -p`를 실행합니다. API 키를 쓰지 않으며 추가 결제가 없고, Pro 사용 한도에서 차감됩니다.
- **본인 PC에서 본인 계정으로 시연하는 용도입니다.** 다른 사람에게 서비스로 제공하려면 API 키 방식으로 바꿔야 합니다.
- 실행 전에 `claude auth status`로 구독 로그인인지 확인합니다. API 키 관련 환경 변수는 지우고 실행합니다.
- 빈 작업 폴더에서 실행하고, 조사 단계에는 `WebSearch`와 `WebFetch`만, 디자인 단계에는 도구를 주지 않습니다. 프로젝트 파일과 커넥터를 읽지 않습니다.
- 로그인이 만료되면 터미널에서 `claude auth login`을 실행합니다.
- **도구 허용이 빠지지 않게:** 지시문은 명령줄이 아니라 임시 파일(`--system-prompt-file`)로 넘기고 실행 후 지웁니다. 명령줄 인자에는 줄바꿈을 넣지 않습니다. npm으로 설치한 `claude.cmd`는 그 안의 `claude.exe`를 찾아 직접 실행합니다. `cmd.exe`는 줄바꿈 뒤 인자를 버려서, 예전에는 검색이 "Claude requested permissions to use WebSearch, but you haven't granted it yet."으로 모두 거절됐습니다 (2026-11-20).
- CLI가 시작하면서 알려 주는 권한 모드와 도구 목록이 요청(`dontAsk`, 요청한 도구만)과 다르면 결과를 쓰지 않고 "실행 설정이 전달되지 않았어요" 오류로 멈춥니다.
- 모델은 환경 변수 `SEMOGWI_CONTENT_MODEL`, `SEMOGWI_DESIGN_MODEL`로 바꿀 수 있습니다 (기본 `sonnet`).

**한도 절약:** 조사는 작업당 1회입니다. 구성안 재생성은 저장된 조사 결과를 재사용하고, 디자인은 5장을 한 번에 만들며, 재시도는 1회입니다. 구성안을 고쳐도 지금 레이아웃에 들어가면 AI를 부르지 않습니다. 다운로드에서는 AI를 호출하지 않습니다.

## 출처 검증

모델이 적은 URL을 믿지 않고 실제 도구 기록과 대조합니다.

| 표시 | 뜻 |
| --- | --- |
| 페이지 읽음 | `WebFetch`가 이 주소를 정상 응답으로 읽음. **확인된 출처는 이것뿐입니다** |
| 검색 목록에만 있음 | `WebSearch` 결과에 주소만 있음. 확인된 출처가 아님 |
| 미확인 | 기록에 없음 |
| 자동 접근 금지 | 금지 사이트의 주소. 자동으로 읽은 근거로 쓰지 않음 |
| 사용자 제공 | 사용자가 입력한 자료 |

- 굿즈·팝업스토어·콜라보는 공식 페이지를 읽은 근거가 없는 카드를 승인할 수 없습니다. 사용자가 직접 수정하면 경고로 바뀝니다.
- **검증되는 것은 "그 주소를 실제로 봤는지"입니다.** 문장이 그 페이지 내용과 일치하는지는 검증하지 않습니다. 등록되지 않은 사이트의 공식 여부는 AI의 판단입니다.

## 사이트 접근 정책

이용 조건이 자동 수집을 금지한다고 확인된 사이트는 자동으로 접근하지 않습니다. 현재는 치이카와 마켓이 해당합니다. 이 주소를 넣으면 AI 호출 없이 자료 입력 화면으로 이동하고, 원하면 그 사이트를 뺀 다른 출처만 자동 조사할 수 있습니다. 다른 사이트의 자동 조사는 유지됩니다.

목록은 `app/site_policy.json`에서 관리합니다. 등록 기준과 오류별 대기 시간은 `docs/site-access-policy.md`에 있습니다. 2026-11-20 팀 결정으로 터미널(`/cardnews`)도 같은 사이트를 읽지 않습니다. `fetch_product.py`는 삭제했고, 저장소의 `.claude/settings.json`이 같은 차단 규칙을 갖고 있습니다 (같은 문서 4절).

## 공식 사이트에 접속하지 못할 때

공식 사이트가 HTTP 429 등으로 막아 자료가 부족하면 제작을 끝내지 않고 **자료 입력 대기** 상태가 됩니다. 조사 기록은 보존되고(조사 완료로 기록 · 보관함에 새 버전), 다시 검색하지 않습니다.

- **부족 판단은 안내로만 씁니다.** 화면에 '부족한 정보'를 항목별로 보여 줍니다 — **찾지 못함**(카드에 만들어 넣지 않고 비움)과 **근거 약함**(출처끼리 다름·근거를 확인하지 못함)을 나눕니다 (`job.researchGap`, `research.gap_report`). 공식 확인이 없다는 이유로는 부족하다고 보지 않습니다 (2차 자료·값이 적힌 검색 결과도 찾은 것).
- **현재 자료로 구성안 작성:** 다시 검색하지 않고 구성안만 씁니다(AI 1회, `POST /research/compose-current`). AI가 또 '부족'이라고 해도 카드가 있으면 진행합니다. 찾지 못한 값은 비우고 지어내지 않습니다. 진행을 골랐다는 기록(`researchStage.forced`)은 출처 종류와 따로 둡니다.
- **자료 보완하기:** 직접 입력, 상세 이미지, 추가 조사(이 상태에서도 사용 가능), 자동 조사 다시 시도(사이트 대기 시간 유지).
- **자료 직접 입력:** '추가로 알려주고 싶은 정보'(자유 입력, 유형별 안내·예시)가 기본이고, 공식 출처·참고 자료 묶음(URL · 출처 종류 · 복사한 내용)을 3개까지 더합니다. 기존 세부 항목(상품명·가격 등)은 접어 두고 필요할 때 펼칩니다. 하나라도 입력하면 제출할 수 있고, 제출한 뒤에는 같은 부족 판단으로 다시 막지 않습니다. 모든 입력은 사용자 제공(`user1`~`user4`, `user_provided`)이며 '공식 출처'를 골라도 공식 확인으로 바뀌지 않습니다. 사용자가 준 나무위키 자료는 모든 유형에서 받고(2차 자료 표시), 미러 주소는 받지 않습니다.
- 이때 AI에게 웹 도구를 주지 않아 **막힌 사이트에 다시 요청하지 않습니다.**
- 접속을 막은 사이트는 작업과 상관없이 사이트 단위로 기다립니다. 대기 시간은 `docs/site-access-policy.md`를 따릅니다. 대기 중인 사이트는 도구 차단 규칙으로 막지만, 한 번의 조사 안에서 처음 실패한 직후의 재시도는 프롬프트로만 막습니다.

| 저장 위치 | 내용 |
| --- | --- |
| `job.userMaterial` | 사용자가 입력한 원문 |
| `research.sources[].origin`, `verification` | `user` / `user_provided`. 입력한 URL도 확인된 출처로 표시하지 않음 |
| `research.facts[].origin` | `ai`(조사) 또는 `user`(사용자 제공) |
| `research.fetchFailures` | 접속 실패한 사이트, 상태 코드, 시도 횟수, 오류 원문(`detail`) |
| `research.searchFailures` | 실패한 검색어, 이유(검색 도구 오류·사용 거부·결과 없음), 오류 원문(`detail`) |

- **카드 출처 문구는 서버가 적습니다.** AI가 쓴 출처 문구는 쓰지 않고, 그 카드가 실제로 인용한 출처(`sourceIds`)의 이름만 적습니다 (`ai_provider._label_user_sources`, AI 생성·다시 쓰기·유형 바꾸기·자료 입력·친구 카드 다시 쓰기 모두). 예: `출처: 공식 숍 · news.example`.
  - 출처 이름이 14자를 넘으면 사이트 주소로 적고, 30자를 넘으면 앞의 것만 적은 뒤 `외 N곳`을 붙입니다. 이름 하나가 30자를 넘어도 빈칸으로 두지 않고 줄여 적습니다.
  - 사용자 자료는 `사용자 제공`(사용자가 준 출처 주소가 있으면 `사용자 제공 · 사이트 주소`), 상세 이미지는 `상세 이미지`. 세부 항목의 '판매처' 칸 값은 출처가 아니라 쓰지 않습니다.
  - 조회 기록에 없는 출처·미러·자동 수집 금지 사이트는 적지 않습니다. 실제 출처가 하나도 없으면 비워 두고 구성안에서 '출처가 비어 있어요'로 알립니다. 표지에는 출처를 두지 않습니다.
  - 구성안에서 직접 고치면 사용자가 쓴 대로 들어갑니다. AI가 카드를 다시 쓰면 다시 서버가 적습니다.
- **검증 기준:** 출처 충돌·검색 결과만(원문 미확인)·근거 문장이 없는 값은 **경고**로 알리고 막지 않습니다. 카드 그림에 '(확인 필요)' 같은 문구는 자동으로 넣지 않습니다. 계속 막는 것은 지어낸 내용입니다:
  - 굿즈·팝업·콜라보에서 **자료에 없는 숫자**(가격, 날짜, 수량): 1회 자동으로 다시 쓰게 하고, 그래도 남으면 승인을 막습니다 (직접 고치면 경고).
  - **출처가 없는 사실**(근거 URL이 조회 기록에 없음): 굿즈·팝업·콜라보는 직접 고치기 전까지 승인을 막습니다. 캐릭터 소개는 경고.
  - 숫자 대조 근거: 읽은 페이지(공식·2차·나무위키), 사용자 자료, 상세 이미지, 그리고 원문을 읽지 못한 검색 결과 중 **조사 항목의 값과 근거 문장이 서로 맞는 값**. 검색 결과 출처를 단 사실 문장만으로는 인정하지 않습니다 (서버는 검색 결과 요약문을 받지 못해 원문을 확인할 수 없음 — 화면에 '원문 미확인'으로 표시). 미러와 조회 기록에 없는 출처는 근거가 아닙니다.
  - **조사에서 찾지 못한 정보:** 카드 칸의 값이 조사 항목·조사 사실·사용자 자료 어디에도 없으면 '조사에서 찾지 못함'으로 표시합니다(다른 칸의 출처 상태를 따라 '공식 확인'으로 보이지 않음). 표기를 바꾼 값(¥440 ↔ 440엔, 12월 1일 ↔ 12.1)은 숫자·낱말로 맞춰 봅니다. AI가 쓴 한 줄 사실 칸(가격·날짜·장소·명칭 등 공식 우선이거나 바뀌기 쉬운 항목, 꼭 필요한 칸 제외)은 자동으로 비우고 구성안에 '비웠어요'로 알립니다. 나머지는 경고만 하고 막지 않습니다.
  - **사용자 작성:** 사용자가 구성안에서 직접 고친 칸은 '사용자 작성'으로 조사한 사실과 구분합니다 (`card.userFields`). AI가 카드를 다시 쓰면 지워집니다.
  - **출처 종류 표시:** 구성안 목록·편집 화면과 PNG 저장 전 경고에 중요 정보(공식 우선·변동·핵심 항목)의 출처 종류를 글로 보여 줍니다 — 공식 확인 / 2차 자료 / 검색 결과(원문 미확인) / 사용자 제공 / 사용자 작성 / 상세 이미지 / 출처 충돌 / 조사에서 찾지 못함. 막지는 않습니다.
- **변동 정보(가격·기간·운영 시간 등):** 출처마다 원문 게시일(`sources[].publishedAt`, 보이는 경우만)과 조사일(`evidence[].at`)을 따로 기록해 조사 결과에 보여 줍니다. 원문 게시일이 조사일보다 30일 넘게 오래되면 구성안에서 최신 정보인지 확인하라고 알립니다(경고).
- **저장 전 경고:** 디자인 승인 화면과 PNG 받기 화면에 확인할 정보(자료 부족 상태로 작성, 출처 충돌·근거 약함, 사용자 제공·이미지 판독, 변동 정보의 원문 게시일·조사일)를 보여 주고, 처음 저장할 때 한 번 확인창을 띄웁니다. 승인과 저장은 막지 않습니다 (`outline.publishWarnings`).
- **상품명과 판매처는 자동으로 대조하지 않습니다.** 프롬프트로 금지하고 경고를 표시하므로 사용자가 확인해야 합니다.

## 승인된 문구 보호

AI는 디자인 단계에서 좌표와 색만 출력합니다. 문구는 서버가 승인된 구성안에서 넣고, 다른 문구가 들어가면 거부합니다. 구성안을 고치면 구성안·디자인 승인이 모두 해제되고, 디자인을 고치면 디자인 승인만 해제됩니다.

## 디자인 검증 (`app/design.py`)

| 문제 | 처리 |
| --- | --- |
| 글자색 대비 부족, 읽기 어려운 배경 | 자동 수정 |
| 여백을 조금 벗어난 박스, 너무 작은 글자 | 자동 수정 |
| 글자와 겹치는 진한 장식 | 옅게 수정, 항상 글자 아래에 그림 |
| 글자가 조금 넘침 | 아래 빈 공간까지 박스 확장 |
| 글자·이미지 겹침, 박스에 안 들어가는 글자, 없는 이미지, 필수 텍스트 누락 | 거부 후 그 카드만 1회 재생성, 그래도 실패하면 오류 표시 |

브라우저에서 실제로 그렸을 때 글자가 칸을 넘치면 최종 승인을 막습니다.

## 배경 제거

- 시스템 Python(`py`)으로 `scripts/cutout.py`를 별도 프로세스로 실행합니다. 웹 가상환경에 rembg를 설치하지 않습니다.
- **이미 설치된 모델만** 씁니다. 모델이 없으면 내려받지 않고 실패를 알립니다.
- 기본값 "자동"은 먼저 사진인지 단색 배경 일러스트인지 판별합니다 (`app/flat_cutout.py`, 시스템 Python의 numpy·scipy·Pillow).
  - **단색 배경 + 어두운 외곽선 일러스트**: "단색 배경 일러스트 (외곽선 기준)" 방법을 씁니다. 흰색 픽셀을 지우지 않고, 이미지 가장자리와 **이어진** 배경색만 투명하게 합니다. 끊긴 외곽선은 먼저 이어서(닫힘 연산, 틈 크기에 맞춰 반경을 키움) 흰 몸통이 틈으로 지워지지 않게 합니다. 틈이 너무 커서 막히지 않으면 결과를 만들지 않고 AI 모델로 넘어갑니다.
  - **사진(또는 위 방법을 쓸 수 없을 때)**: 실물 사진용(`isnet-general-use`) → 그림용(`isnet-anime`) → `u2net` → `bria-rmbg` 순서로 시도해 검사를 통과한 첫 결과를 씁니다.
  - 일러스트에 AI 모델 결과를 쓸 때는 외곽선이 둘러싼 영역이 90% 이상 남았는지 추가로 검사합니다. 외곽선이 끊겨 있으면 지워진 몸통이 바깥과 이어져 '안쪽 구멍' 검사에 걸리지 않기 때문입니다.
- 실패하면 결과 파일을 지우고 원본을 그대로 씁니다. 자리마다 "원본 복원"으로 언제든 원본으로 돌아갈 수 있습니다.
- 검사(`app/alpha_check.py`): 배경이 남았는지, 피사체 안쪽(흰 몸통·얼굴)이 뚫렸는지(holes), 털 인형처럼 몸통이 반투명하게 남았는지(translucent)를 봅니다. 알파 보정은 `app/alpha_refine.py`.
- 누끼가 끝나면 그 이미지를 쓰는 카드 자리에 자동으로 반영합니다. 그 자리에서 원본을 직접 고른 경우는 원본을 유지합니다.
- 원본과 이전 결과는 덮어쓰지 않습니다. 결과는 `data/jobs/<id>/uploads/<이미지 id>-cutout-<번호>.png`에 투명 PNG로 저장합니다.

## 문구 규칙

제목 20자, 본문 80자, 출처 30자(`출처: `로 시작) 오류 기준과 제목 16자, 본문 2줄 경고 기준은 `scripts/fill_figma.py`와 같습니다. 한 줄 42자 경고는 Figma의 글자 단위 줄바꿈 때문에 생긴 규칙이라 적용하지 않습니다. 세모귀 말투와 유형별 규칙은 Skill에서 `app/ai_rules.py`로 옮겼고, Skill 파일은 수정하지 않았습니다.

개발 중에는 주소 뒤에 `?debug=1`을 붙이면 기능별 구현 상태 표를 볼 수 있습니다. 카드 템플릿 글꼴(Jua, Gowun Dodum)은 `static/fonts/`에 들어 있어 인터넷 없이도 같은 모양으로 그립니다. 화면의 나머지 글꼴은 Google Fonts에서 불러오며, 인터넷이 없으면 맑은 고딕으로 대체됩니다.
