# 세모귀 웹 (로컬 전용)

웹페이지에서 주제를 입력하면 AI가 자료를 조사하고 카드뉴스 5장의 문구와 디자인을 만들어 PNG로 내보내는 프로그램입니다. 사용자는 구성안과 디자인을 각각 확인·수정·승인합니다.

## 설치와 실행 (팀원용)

### 1. 필요한 프로그램

| 프로그램 | 용도 | 필수 |
| --- | --- | --- |
| Windows + Python 3.11 이상 (`py` 실행기 포함, 개발 환경은 3.13) | 웹 서버 | 필수 |
| 시스템 Python의 `rembg`, `Pillow`, `onnxruntime` + 누끼 모델 파일 | 배경 제거 | 선택 |
| Claude Code CLI (`claude`), Claude 구독 로그인 | 실제 AI 조사·문구 | 선택 (없으면 데모 모드만) |

### 2. 코드 받기

```
git clone https://github.com/JaneAhn38/semogwi.git
cd semogwi
git switch feature/web-app      (main에 병합되기 전)
```

### 3. 웹 서버 실행

`web` 폴더의 `run.bat`을 더블클릭한 뒤 브라우저에서 **http://127.0.0.1:8000** 을 엽니다. 처음 실행하면 `web/.venv` 가상환경을 만들고 `requirements.txt`(FastAPI, uvicorn, python-multipart, pytest, httpx)를 설치합니다. 끄려면 창에서 `Ctrl+C`를 누릅니다.

터미널로 직접 실행:

```
cd web
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

테스트: `.venv\Scripts\python -m pytest tests -q` (Claude를 호출하지 않아 한도가 차감되지 않고, 배경 제거 모델도 쓰지 않습니다)

### 4. 배경 제거 준비 (선택)

배경 제거는 웹 가상환경이 아니라 **시스템 Python**(`py`)으로 `scripts/cutout.py`를 실행합니다. 웹에서는 모델을 자동으로 내려받지 않으므로 한 번 직접 내려받아 둡니다.

```
py -m pip install "rembg[cpu]" pillow
py scripts\cutout.py 아무사진.jpg 결과.png --model isnet-general-use
py scripts\cutout.py 아무사진.jpg 결과.png --model u2net
py scripts\cutout.py 아무사진.jpg 결과.png --model isnet-anime
```

모델 파일은 `%USERPROFILE%\.rembg` (또는 `.u2net`)에 저장되고 저장소에는 포함하지 않습니다. 모델이 하나도 없으면 화면에 "배경 제거를 쓸 수 없어요"가 뜨고 원본 이미지는 그대로 쓸 수 있습니다. `bria-rmbg`(고품질)는 비상업용 라이선스(CC BY-NC 4.0)라 필요한 경우에만 각자 받으세요.

### 5. 실제 AI 모드 준비 (선택)

[Claude Code](https://docs.claude.com/claude-code)를 설치하고 터미널에서 `claude auth login`으로 본인 구독 계정에 로그인합니다. API 키나 `.env` 파일은 쓰지 않습니다. 설치하지 않으면 데모 모드로만 동작합니다.

### Git에 올리지 않는 것

`web/.venv/`, `web/data/`(업로드 이미지·작업 기록·AI 작업 폴더), `__pycache__/`, `.pytest_cache/`는 `web/.gitignore`로 제외합니다. 업로드한 사진은 각자 PC에만 남습니다.

## 제작 방식

| | 실제 AI | 데모 |
| --- | --- | --- |
| 유형 | "AI가 판단"이면 조사 전에 짧게 판단 (웹 없음) | 주제 키워드로 추정 |
| 조사·문구 | Claude가 웹을 검색해 템플릿 필드를 채움 | 예시 문구, 조사 안 함 |
| 디자인 | 팀이 만든 고정 템플릿 (AI 호출 없음) | 같음 |
| PNG | 표시 없음 | `DEMO SAMPLE` 표시 |
| Pro 한도 | 조사 단계에서 차감 | 차감 없음 |

AI 호출이 실패하면 데모 결과로 대신하지 않고 이유를 표시합니다. 조사 단계는 **다시 시도** 버튼으로, 카드 문구는 다시 요청해서 이어 갈 수 있고 그동안 기존 결과는 유지됩니다.

## 카드 이미지 (구성안 단계)

- 카드의 이미지 자리마다 이미지를 고르거나, 그 자리에서 바로 올려 넣거나 교체할 수 있습니다 (사용 권한 '허가됨'과 출처 필요).
- 올린 이미지는 빈 자리에 **추천만** 표시합니다. **적용**을 눌러야 카드에 들어갑니다.
- 자리마다 배경 제거 ON/OFF, 원본·누끼 비교, 원본 복원, 크기(30~300%)·위치 조정을 할 수 있고 값은 작업 데이터(`slotImages`)에 저장됩니다.
- 누끼는 투명 여백을 빼고 피사체 기준으로 자리의 90%에 맞춥니다. 이미지가 없는 자리는 PNG에 아무것도 그리지 않습니다(마스코트 자리표시 없음).
- 화면, PNG 파일 이름(`semogwi-card-01.png` ~ `05`), ZIP 안의 순서는 모두 card-01 ~ card-05입니다.

## 고정 템플릿 (4유형 × 5장)

새 작업은 팀이 만든 PNG 디자인 20장을 옮긴 고정 템플릿으로 만듭니다. 유형마다 card-01 ~ card-05의 디자인이 정해져 있고, AI는 디자인을 만들지 않고 각 카드의 필드(이름, 가격, 기간 등)만 씁니다.

- 3단계 구성안에서 카드마다 템플릿 미리보기를 보며 필드와 이미지 자리를 고칩니다. 입력하는 즉시 미리보기가 바뀝니다.
- 디자인 유형은 자동으로 정해지고, 구성안 단계에서 직접 바꿀 수 있습니다.
- 비워 둔 선택 항목은 카드에서 숨깁니다. 자리표시 문구(`[캐릭터 이름]` 등)는 저장할 수 없습니다.
- 이미지 자리가 여러 개인 카드(굿즈 라인업 4개 등)는 자리마다 이미지를 고릅니다.
- 이전 작업(AI 디자인, 표지 + 본문 반복 템플릿)은 만들어진 방식 그대로 열립니다.
- 규격과 비교 결과: `docs/template-spec.md`

### 조사 항목과 참고 자료

- 입력 화면의 **참고 자료 직접 입력**에 공식 공지·판매 페이지에서 확인한 내용을 붙여 넣으면, AI가 조사할 때 함께 읽고 카드에는 **사용자 제공** 자료로 표시합니다. 데모에서는 저장만 합니다.
- 실제 AI 조사는 유형별 항목(캐릭터: 이름·첫 등장·성격…, 팝업: 기간·운영 시간·장소·휴무일…)을 하나씩 찾고, 2단계 **자료 조사 결과**에 항목마다 상태(공식 확인, 2차 자료, 사용자 제공, 출처 충돌, 정보 확인 필요 등), 근거 문장, 출처 링크를 보여 줍니다.
- 찾지 못한 항목은 지어내지 않고 **정보 확인 필요**로 남깁니다. **카드에서 입력**을 누르면 그 항목을 쓰는 카드 편집으로 이동합니다. 구성안의 필드마다 같은 상태 배지가 붙습니다.
- 같은 항목에 출처마다 다른 값이 나오면 **출처 충돌**로 값을 모두 보여 주고, 가격·일정·장소 같은 항목은 사용자가 확인해 고칠 때까지 승인을 막습니다.
- 검색 실패, 접속 실패, 자동 접근 금지 사이트는 **조사 중 문제**에 이유별로 표시합니다.

화면을 새로 고쳤는데 예전 화면이 보이면 Ctrl+F5로 새로 고침해 주세요. 지금은 화면 파일을 매번 확인하도록 서버가 알려 주므로 다시 생기지 않습니다.

## 실제 AI 연결

- 이 PC에 로그인된 Claude 구독으로 `claude -p`를 실행합니다. API 키를 쓰지 않으며 추가 결제가 없고, Pro 사용 한도에서 차감됩니다.
- **본인 PC에서 본인 계정으로 시연하는 용도입니다.** 다른 사람에게 서비스로 제공하려면 API 키 방식으로 바꿔야 합니다.
- 실행 전에 `claude auth status`로 구독 로그인인지 확인합니다. API 키 관련 환경 변수는 지우고 실행합니다.
- 빈 작업 폴더에서 실행하고, 조사 단계에는 `WebSearch`와 `WebFetch`만, 디자인 단계에는 도구를 주지 않습니다. 프로젝트 파일과 커넥터를 읽지 않습니다.
- 로그인이 만료되면 터미널에서 `claude auth login`을 실행합니다.
- 모델은 환경 변수 `SEMOGWI_CONTENT_MODEL`, `SEMOGWI_DESIGN_MODEL`로 바꿀 수 있습니다 (기본 `sonnet`).

**한도 절약:** 조사는 작업당 1회입니다. 구성안 재생성은 저장된 조사 결과를 재사용하고, 디자인은 5장을 한 번에 만들며, 재시도는 1회입니다. 구성안을 고쳐도 지금 레이아웃에 들어가면 AI를 부르지 않습니다. 다운로드에서는 AI를 호출하지 않습니다.

## 출처 검증

모델이 적은 URL을 믿지 않고 실제 도구 기록과 대조합니다.

| 표시 | 뜻 |
| --- | --- |
| 페이지 읽음 | `WebFetch`가 이 주소를 정상 응답으로 읽음. **확인된 출처는 이것뿐입니다** |
| 검색 목록에만 있음 | `WebSearch` 결과에 주소만 있음. 확인된 출처가 아님 |
| 미확인 | 기록에 없음 |
| 자동 접근 금지 | 금지 사이트의 주소. 자동으로 읽은 근거로 쓰지 않음 |
| 사용자 제공 | 사용자가 입력한 자료 |

- 굿즈·팝업스토어·콜라보는 공식 페이지를 읽은 근거가 없는 카드를 승인할 수 없습니다. 사용자가 직접 수정하면 경고로 바뀝니다.
- **검증되는 것은 "그 주소를 실제로 봤는지"입니다.** 문장이 그 페이지 내용과 일치하는지는 검증하지 않습니다. 등록되지 않은 사이트의 공식 여부는 AI의 판단입니다.

## 사이트 접근 정책

이용 조건이 자동 수집을 금지한다고 확인된 사이트는 자동으로 접근하지 않습니다. 현재는 치이카와 마켓이 해당합니다. 이 주소를 넣으면 AI 호출 없이 자료 입력 화면으로 이동하고, 원하면 그 사이트를 뺀 다른 출처만 자동 조사할 수 있습니다. 다른 사이트의 자동 조사는 유지됩니다.

목록은 `app/site_policy.json`에서 관리합니다. 등록 기준, 오류별 대기 시간, `fetch_product.py`와 `/cardnews`의 제한 사항은 `docs/site-access-policy.md`에 있습니다.

## 공식 사이트에 접속하지 못할 때

공식 사이트가 HTTP 429 등으로 막아 자료가 부족하면 제작을 끝내지 않고 **자료 입력 대기** 상태가 됩니다. 조사 기록은 보존됩니다.

- 상품명, 가격, 특징, 판매처, 공식 출처 URL을 입력하거나 공식 페이지 내용을 붙여 넣으면 구성안을 이어서 만듭니다. 이름과 특징, 또는 20자 이상의 붙여 넣은 내용이 필요합니다.
- 이때 AI에게 웹 도구를 주지 않아 **막힌 사이트에 다시 요청하지 않습니다.**
- 접속을 막은 사이트는 작업과 상관없이 사이트 단위로 기다립니다. 대기 시간은 `docs/site-access-policy.md`를 따릅니다. 대기 중인 사이트는 도구 차단 규칙으로 막지만, 한 번의 조사 안에서 처음 실패한 직후의 재시도는 프롬프트로만 막습니다.

| 저장 위치 | 내용 |
| --- | --- |
| `job.userMaterial` | 사용자가 입력한 원문 |
| `research.sources[].origin`, `verification` | `user` / `user_provided`. 입력한 URL도 확인된 출처로 표시하지 않음 |
| `research.facts[].origin` | `ai`(조사) 또는 `user`(사용자 제공) |
| `research.fetchFailures` | 접속 실패한 사이트, 상태 코드, 시도 횟수 |

- 사용자 자료만 근거인 카드는 출처 문구를 `출처: 판매처 (사용자 제공)`으로 서버가 맞추므로 PNG에도 남습니다. 직접 수정하면 사용자가 쓴 대로 들어갑니다.
- 굿즈·팝업·콜라보에서 자료에 없는 숫자(가격, 날짜, 수량)가 문구에 있으면 1회 다시 쓰게 하고, 그래도 남으면 승인을 막습니다.
- **상품명과 판매처는 자동으로 대조하지 않습니다.** 프롬프트로 금지하고 경고를 표시하므로 사용자가 확인해야 합니다.

## 승인된 문구 보호

AI는 디자인 단계에서 좌표와 색만 출력합니다. 문구는 서버가 승인된 구성안에서 넣고, 다른 문구가 들어가면 거부합니다. 구성안을 고치면 구성안·디자인 승인이 모두 해제되고, 디자인을 고치면 디자인 승인만 해제됩니다.

## 디자인 검증 (`app/design.py`)

| 문제 | 처리 |
| --- | --- |
| 글자색 대비 부족, 읽기 어려운 배경 | 자동 수정 |
| 여백을 조금 벗어난 박스, 너무 작은 글자 | 자동 수정 |
| 글자와 겹치는 진한 장식 | 옅게 수정, 항상 글자 아래에 그림 |
| 글자가 조금 넘침 | 아래 빈 공간까지 박스 확장 |
| 글자·이미지 겹침, 박스에 안 들어가는 글자, 없는 이미지, 필수 텍스트 누락 | 거부 후 그 카드만 1회 재생성, 그래도 실패하면 오류 표시 |

브라우저에서 실제로 그렸을 때 글자가 칸을 넘치면 최종 승인을 막습니다.

## 배경 제거

- 시스템 Python(`py`)으로 `scripts/cutout.py`를 별도 프로세스로 실행합니다. 웹 가상환경에 rembg를 설치하지 않습니다.
- **이미 설치된 모델만** 씁니다. 모델이 없으면 내려받지 않고 실패를 알립니다.
- 기본값 "자동"은 실물 사진용(`isnet-general-use`) → 그림용(`isnet-anime`) → `u2net` → `bria-rmbg` 순서로 시도해 검사를 통과한 첫 결과를 씁니다.
- 검사(`app/alpha_check.py`): 배경이 남았는지, 피사체 안쪽(흰 몸통·얼굴)이 뚫렸는지(holes), 털 인형처럼 몸통이 반투명하게 남았는지(translucent)를 봅니다. 알파 보정은 `app/alpha_refine.py`.
- 누끼가 끝나면 그 이미지를 쓰는 카드 자리에 자동으로 반영합니다. 그 자리에서 원본을 직접 고른 경우는 원본을 유지합니다.
- 원본과 이전 결과는 덮어쓰지 않습니다. 결과는 `data/jobs/<id>/uploads/<이미지 id>-cutout-<번호>.png`에 투명 PNG로 저장합니다.

## 문구 규칙

제목 20자, 본문 80자, 출처 30자(`출처: `로 시작) 오류 기준과 제목 16자, 본문 2줄 경고 기준은 `scripts/fill_figma.py`와 같습니다. 한 줄 42자 경고는 Figma의 글자 단위 줄바꿈 때문에 생긴 규칙이라 적용하지 않습니다. 세모귀 말투와 유형별 규칙은 Skill에서 `app/ai_rules.py`로 옮겼고, Skill 파일은 수정하지 않았습니다.

개발 중에는 주소 뒤에 `?debug=1`을 붙이면 기능별 구현 상태 표를 볼 수 있습니다. 카드 템플릿 글꼴(Jua, Gowun Dodum)은 `static/fonts/`에 들어 있어 인터넷 없이도 같은 모양으로 그립니다. 화면의 나머지 글꼴은 Google Fonts에서 불러오며, 인터넷이 없으면 맑은 고딕으로 대체됩니다.
