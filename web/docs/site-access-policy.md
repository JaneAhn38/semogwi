# 사이트 접근 정책과 출처 표시 기준

세모귀 웹페이지가 외부 사이트를 어떻게 다루는지 정리한 문서입니다. 사이트 목록은 `app/site_policy.json`에서 관리합니다.

## 1. 사이트 구분

| 구분 | 동작 | 등록 기준 |
| --- | --- | --- |
| 자동 접근 금지 (`restricted`) | AI 호출 없이 자료 입력 화면으로 이동. 이후 호출에서도 `WebFetch` 차단 | 이용 조건에 자동 수집 금지가 확인된 사이트 |
| 등록된 공식 (`official`) | 자동 조사. `공식(등록)`으로 표시 | 사람이 운영 주체를 확인한 사이트 |
| 그 밖의 사이트 | 자동 조사. 공식이라면 `공식(AI 판단)`, 항상 `이용 조건 미확인` 표시 | 없음 |

**현재 목록:** 자동 접근 금지는 치이카와 마켓 1곳입니다. 등록된 공식 사이트는 없습니다. 프로젝트에 운영 주체를 확인한 기록이 없어 비워 두었습니다.

### 치이카와 마켓

이용규약 【금지 사항】 (2026-11-03 저장본, 2026-05-13 개정):

> 당사의 사전 허가를 얻지 않고 자동화된 수단(자동 구입 툴, 로봇 등 이에 준하는 수단)을 이용하여 상품을 구입하거나 기타 본 사이트를 이용하는 행위(상품 페이지상의 정보 취득 등을 포함)

2026-11-20 팀 결정으로 이 사이트에서는 정보를 가져오지 않습니다 (4절). 허가를 받더라도 `restricted`에서 빼려면 팀에서 다시 결정해야 합니다. 규약은 바뀔 수 있으니 다시 검토할 때는 사람이 확인해 주세요. 이 문서는 법률 판단이 아닙니다.

### 보조 출처: 나무위키 (`auxiliary`)

공식 출처가 아닌 **2차 자료**로 모든 콘텐츠 유형에서 참고 근거로 씁니다 (2026-11-23 변경). 이용 조건을 확인 중이라 **자동으로 읽는 범위는 캐릭터 소개로 제한**합니다 (`site_policy.json`의 `auxiliary`, `autoFetch`).

확인 기록 (2026-11-20):
- `robots.txt`: `User-agent: *`에 `Disallow: /` 뒤 `Allow: /w/`(문서) 등을 허용. AI 봇을 따로 지정한 규칙은 없음
- 이용약관: 문서 요청이 403이라 원문을 확인하지 못함. **자동 수집 금지 조항이 확인되면 `restricted`로 옮깁니다**
- 문서 요청: 11-18까지 앱 조사에서 200, 11-20 진단 요청은 Cloudflare 403 (확인 화면이 아닌 차단). 원인은 사이트 쪽 봇 차단으로 추정. 공유 기능(share.bat, Cloudflare Tunnel)은 들어오는 요청만 다루므로 관계없음

규칙:
- 403 차단을 우회하지 않습니다. 실패하면 기존 대기 규칙(1시간)을 그대로 따르고, 다른 출처로 조사를 이어 갑니다.
- 읽는 횟수를 늘리지 않습니다. AI 지시는 제한만 둡니다: 한 번의 조사에서 나무위키 문서는 1개까지, 실패하면 다시 요청하지 않음.
- 근거로 쓰는 항목: 모든 항목 (2차 자료, `secondary`). 공식 출처와 값이 같으면 공식 확인, 다르면 출처 충돌(경고)입니다.
- 굿즈·팝업스토어·콜라보 조사에서는 나무위키 `WebFetch`를 계속 차단합니다 (자동 접근을 넓히지 않음). 이 유형에서는 사용자가 직접 준 나무위키 자료만 씁니다. 읽은 나무위키 자료의 숫자는 숫자 대조 근거로 셉니다.
- AI가 `official`이라고 적어도 `secondary`로 두고 `auxiliary` 표시를 붙입니다. 공식 출처와 값이 같으면 공식 확인, 다르면 출처 충돌(사용자 검토)입니다.
- 미러 사이트(`namu.moe`)는 원본이 아니므로 자동으로 읽지 않고(`WebFetch` 차단), 읽은 기록이 있어도 근거로 인정하지 않습니다(`verification: mirror`).
- 같은 규칙을 최초 조사, 보완 조사, 추가 조사, 저장된 자료(보관함에서 불러올 때)에 똑같이 적용합니다. 저장된 버전 파일은 고치지 않습니다.
- 화면: 출처 옆에 '나무위키(보조 출처)', 조사 항목에 '나무위키 근거 (2차 자료)'·'공식 확인 · 나무위키도 참고' 등을 글자로 표시합니다. 공식이 아니라는 이유만으로 카드에 경고를 띄우지 않습니다.

참고 자료 직접 입력의 **출처 종류**(공식 출처 / 나무위키 / 기타)와 **주소**:
- 어느 종류든 `user_provided`(사용자 제공)입니다. '공식 출처'를 골라도 공식 확인으로 처리하지 않습니다.
- '나무위키'를 고르거나 주소가 namu.wiki면 위 보조 출처 규칙을 따릅니다. 나무위키를 골랐는데 다른 주소면, 또는 미러 주소면 받지 않습니다.
- 자료 입력 화면에서도 모든 유형에서 나무위키 자료를 받습니다 (사용자 제공 · 2차 자료 표시). 미러 주소는 받지 않습니다.

### 사이트 등록 방법

`app/site_policy.json`을 수정하고 서버를 다시 시작합니다. 확인한 날짜와 근거를 함께 적습니다.

- 이용 조건을 읽고 자동 수집 금지가 있으면 `restricted`에 추가합니다.
- 운영 주체를 확인했으면 `official`에 추가합니다: `{"domain": "example.jp", "name": "사이트 이름", "checked": "2026-11-06 운영사 표기 확인"}`

프로그램은 다른 사이트의 이용 조건을 자동으로 판단하지 않습니다. `robots.txt`도 읽지 않으므로, 자동 조사 대상이 정해지면 사람이 확인해야 합니다.

## 2. 출처 표시

| 표시 | 뜻 | 확인된 출처인가 |
| --- | --- | --- |
| 페이지 읽음 | 이번 작업의 `WebFetch` 기록에 정상 응답이 있음 | 예 |
| 검색 결과 (원문 미확인) | 검색 결과에 주소와 값이 있고 페이지는 읽지 않음. 값과 근거 문장이 있으면 참고 자료로 씀 | 원문 미확인으로 따로 표시 |
| 미확인 | 도구 기록에 없음 | 아니요 |
| 자동 접근 금지 | 금지 사이트의 주소. 자동으로 읽은 근거로 쓰지 않음 | 아니요 |
| 사용자 제공 | 사용자가 입력한 자료. 입력한 URL도 포함 | 아니요, 별도 구분 |

"페이지 읽음"도 **그 주소를 실제로 봤다는 뜻**입니다. 문장이 페이지와 일치하는지는 검증하지 않으니 사용자가 확인해야 합니다.

| 유형 | 출처가 없는 카드 (조회 기록에 없음) | 검색 결과만 있는 카드 | 2차 출처만 있는 카드 |
| --- | --- | --- | --- |
| 캐릭터 소개 | 경고 | 경고 | 허용 |
| 굿즈, 팝업스토어, 콜라보 | 승인 차단. 직접 수정하면 경고로 변경 | 경고 | 허용 (2026-11-23부터. 공식 출처는 우선 참고일 뿐 필수 아님) |

사용자 제공 자료만 근거인 카드는 경고와 함께 승인할 수 있고, 카드 출처에 `(사용자 제공)`이 남습니다.

굿즈, 팝업스토어, 콜라보에서는 문구의 숫자를 "읽은 페이지(공식·2차)와 값이 적힌 검색 결과의 사실"과 "사용자 제공 자료"에 대조합니다. 없는 숫자는 지어낸 것일 수 있어 승인을 막습니다. 상품명과 판매처는 자동으로 대조하지 않습니다.

## 3. 접속 실패 처리

| 응답 | 화면 안내 | 사이트 대기 시간 |
| --- | --- | --- |
| 429, 503 | 요청 제한, 일시 장애 | `Retry-After`와 5분 중 긴 값, 값이 없으면 10분 |
| 401, 402, 403, 451 | 자동 접근 허용 안 함 | 1시간 |
| 404, 410 | 페이지 없음 | 없음 |
| 그 밖의 5xx, 접속 실패 | 사이트 오류, 접속 실패 | 5분 |

- 대기는 **사이트 단위**입니다 (`data/site-cooldowns.json`). 새 작업을 만들어도 대기 중인 사이트에는 요청하지 않습니다.
- 대기 중인 사이트와 금지 사이트는 `--disallowedTools`에 `WebFetch(domain:도메인)`과 `WebFetch(domain:*.도메인)`을 함께 넣어 차단합니다. 도메인 자체와 모든 깊이의 하위 도메인이 막힙니다. 프롬프트로도 재요청을 금지합니다.
- 와일드카드 규칙은 Claude Code v2.1.172 이상이 필요합니다. 이 PC는 v2.1.319입니다. 금지 사이트 판별(입력 화면 이동, 출처 인정 거부)도 하위 도메인까지 적용됩니다.
- **실제 검증 (2026-11-09, 1회):** 치이카와 마켓에 요청하지 않도록 예약 도메인 `example.com`을 같은 코드로 금지 목록에 넣었습니다. `example.com`, `www.example.com`, `a.b.example.com`은 요청 전에 `WebFetch denied access to domain:...`로 거부됐고, 차단하지 않은 `example.org`만 읽혔습니다. 거부된 요청은 사이트 접속 실패로 기록되지 않습니다.
- **거부 표시 기준:** 도구가 읽기를 거부했다고 답해도, 그 사이트가 우리 차단 규칙(금지 사이트, 대기 중 사이트)에 있을 때만 "접근 제한 규칙으로 요청하지 않았어요"로 표시합니다(`site_policy.blocked_by_rule`). 그 밖의 거부는 "읽기 실패 (오류 내용: …)"로 표시하고, 사이트 탓인지 알 수 없으므로 대기 시간을 두지 않습니다.
- 한 번의 조사 안에서 처음 실패한 뒤 바로 재시도하는 것은 프롬프트로만 막습니다. 차단 규칙은 다음 호출부터 적용됩니다.
- 서버는 금지 사이트의 기록을 "페이지 읽음"으로 인정하지 않습니다. 차단 규칙이 실패해도 확인된 출처가 되지 않습니다.

## 4. 결정 (2026-11-20): 치이카와 마켓에서 정보를 가져오지 않음

이전에는 터미널 쪽 팀 공용 기능이 치이카와 마켓에 자동으로 접속했고, 이 문서에 "팀에서 결정이 필요하다"고 남겨 두었습니다. 팀은 이 사이트에서 정보를 가져오지 않기로 정했습니다. 웹앱과 터미널이 같은 차단 규칙을 따릅니다.

| 이전 기능 | 위치 | 정리한 내용 |
| --- | --- | --- |
| 공식 상품 URL 수집 | `scripts/fetch_product.py` | **삭제.** 상품 JSON, 상품 페이지, 이미지를 받던 스크립트이고, 허용 주소가 치이카와 마켓뿐이었습니다. 이전 코드는 git 기록에만 남습니다 |
| URL 입력 흐름 | `.claude/commands/cardnews.md`, `.claude/skills/analyze-image/SKILL.md`, `templates/cardnews-pipeline.md` | **삭제.** 입력은 주제·사진 두 가지입니다. 금지 사이트 주소가 들어오면 열지 않고, 직접 본 내용이나 캡처를 받아 사용자 제공 자료로 다룹니다 (웹앱과 같은 기준) |
| `research-topic`의 추가 조사 | `.claude/skills/research-topic/SKILL.md` | 금지 사이트는 검색 결과에 나와도 읽지 않고 출처로 쓰지 않는다는 규칙을 넣었습니다 |
| 카드 이미지 | `.claude/skills/cutout-image/SKILL.md` | 금지 사이트에서 내려받은 이미지는 카드에 쓰지 않습니다 |

**터미널 차단 규칙:** 저장소의 `.claude/settings.json`에 웹앱이 CLI에 넘기는 것과 같은 규칙을 넣었습니다. 이 저장소에서 여는 모든 Claude Code 세션(`/cardnews` 포함)에서 `WebFetch`가 이 사이트에 요청하지 못합니다.

```json
{ "permissions": { "deny": ["WebFetch(domain:chiikawamarket.jp)", "WebFetch(domain:*.chiikawamarket.jp)"] } }
```

- **실제 검증 (2026-11-20, 1회):** 치이카와 마켓에 요청하지 않도록, 빈 폴더에 같은 형식으로 `example.com`을 막는 `.claude/settings.json`을 두고 `WebFetch`를 허용한 채 실행했습니다. `www.example.com` 요청이 거부됐습니다.
- **금지 사이트를 추가할 때:** `app/site_policy.json`의 `restricted`와 `.claude/settings.json`의 `deny`에 함께 넣습니다. 한쪽만 넣으면 테스트(`test_terminal_settings_deny_every_restricted_site`)가 실패합니다.
- **막지 못하는 것:** 이 규칙은 Claude의 `WebFetch`만 막습니다. `curl`, 브라우저 자동화, 직접 만든 스크립트는 막지 않습니다. **금지 사이트에 접속하는 스크립트를 새로 만들지 않습니다.**
