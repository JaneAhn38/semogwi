# 사이트 접근 정책과 출처 표시 기준

세모귀 웹페이지가 외부 사이트를 어떻게 다루는지 정리한 문서입니다. 사이트 목록은 `app/site_policy.json`에서 관리합니다.

## 1. 사이트 구분

| 구분 | 동작 | 등록 기준 |
| --- | --- | --- |
| 자동 접근 금지 (`restricted`) | AI 호출 없이 자료 입력 화면으로 이동. 이후 호출에서도 `WebFetch` 차단 | 이용 조건에 자동 수집 금지가 확인된 사이트 |
| 등록된 공식 (`official`) | 자동 조사. `공식(등록)`으로 표시 | 사람이 운영 주체를 확인한 사이트 |
| 그 밖의 사이트 | 자동 조사. 공식이라면 `공식(AI 판단)`, 항상 `이용 조건 미확인` 표시 | 없음 |

**현재 목록:** 자동 접근 금지는 치이카와 마켓 1곳입니다. 등록된 공식 사이트는 없습니다. 프로젝트에 운영 주체를 확인한 기록이 없어 비워 두었습니다.

### 치이카와 마켓

이용규약 【금지 사항】 (2026-11-03 저장본, 2026-05-13 개정):

> 당사의 사전 허가를 얻지 않고 자동화된 수단(자동 구입 툴, 로봇 등 이에 준하는 수단)을 이용하여 상품을 구입하거나 기타 본 사이트를 이용하는 행위(상품 페이지상의 정보 취득 등을 포함)

허가를 받으면 `restricted`에서 뺄 수 있습니다. 규약은 바뀔 수 있으니 시연 전에 사람이 다시 확인해 주세요. 이 문서는 법률 판단이 아닙니다.

### 사이트 등록 방법

`app/site_policy.json`을 수정하고 서버를 다시 시작합니다. 확인한 날짜와 근거를 함께 적습니다.

- 이용 조건을 읽고 자동 수집 금지가 있으면 `restricted`에 추가합니다.
- 운영 주체를 확인했으면 `official`에 추가합니다: `{"domain": "example.jp", "name": "사이트 이름", "checked": "2026-11-06 운영사 표기 확인"}`

프로그램은 다른 사이트의 이용 조건을 자동으로 판단하지 않습니다. `robots.txt`도 읽지 않으므로, 자동 조사 대상이 정해지면 사람이 확인해야 합니다.

## 2. 출처 표시

| 표시 | 뜻 | 확인된 출처인가 |
| --- | --- | --- |
| 페이지 읽음 | 이번 작업의 `WebFetch` 기록에 정상 응답이 있음 | 예 |
| 검색 목록에만 있음 | 검색 결과에 주소만 있고 페이지는 읽지 않음 | **아니요** |
| 미확인 | 도구 기록에 없음 | 아니요 |
| 자동 접근 금지 | 금지 사이트의 주소. 자동으로 읽은 근거로 쓰지 않음 | 아니요 |
| 사용자 제공 | 사용자가 입력한 자료. 입력한 URL도 포함 | 아니요, 별도 구분 |

"페이지 읽음"도 **그 주소를 실제로 봤다는 뜻**입니다. 문장이 페이지와 일치하는지는 검증하지 않으니 사용자가 확인해야 합니다.

| 유형 | 확인된 출처가 없는 카드 | 2차 출처만 있는 카드 |
| --- | --- | --- |
| 캐릭터 소개 | 경고 | 허용 |
| 굿즈, 팝업스토어, 콜라보 | 승인 차단. 직접 수정하면 경고로 변경 | 승인 차단. 직접 수정하면 경고로 변경 |

사용자 제공 자료만 근거인 카드는 경고와 함께 승인할 수 있고, 카드 출처에 `(사용자 제공)`이 남습니다.

굿즈, 팝업스토어, 콜라보에서는 문구의 숫자를 "읽은 페이지의 사실"과 "사용자 제공 자료"에 대조합니다. 없는 숫자는 승인을 막습니다. 상품명과 판매처는 자동으로 대조하지 않습니다.

## 3. 접속 실패 처리

| 응답 | 화면 안내 | 사이트 대기 시간 |
| --- | --- | --- |
| 429, 503 | 요청 제한, 일시 장애 | `Retry-After`와 5분 중 긴 값, 값이 없으면 10분 |
| 401, 402, 403, 451 | 자동 접근 허용 안 함 | 1시간 |
| 404, 410 | 페이지 없음 | 없음 |
| 그 밖의 5xx, 접속 실패 | 사이트 오류, 접속 실패 | 5분 |

- 대기는 **사이트 단위**입니다 (`data/site-cooldowns.json`). 새 작업을 만들어도 대기 중인 사이트에는 요청하지 않습니다.
- 대기 중인 사이트와 금지 사이트는 `--disallowedTools`에 `WebFetch(domain:도메인)`과 `WebFetch(domain:*.도메인)`을 함께 넣어 차단합니다. 도메인 자체와 모든 깊이의 하위 도메인이 막힙니다. 프롬프트로도 재요청을 금지합니다.
- 와일드카드 규칙은 Claude Code v2.1.172 이상이 필요합니다. 이 PC는 v2.1.319입니다. 금지 사이트 판별(입력 화면 이동, 출처 인정 거부)도 하위 도메인까지 적용됩니다.
- **실제 검증 (2026-11-09, 1회):** 치이카와 마켓에 요청하지 않도록 예약 도메인 `example.com`을 같은 코드로 금지 목록에 넣었습니다. `example.com`, `www.example.com`, `a.b.example.com`은 요청 전에 `WebFetch denied access to domain:...`로 거부됐고, 차단하지 않은 `example.org`만 읽혔습니다. 거부된 요청은 사이트 접속 실패로 기록되지 않습니다.
- 한 번의 조사 안에서 처음 실패한 뒤 바로 재시도하는 것은 프롬프트로만 막습니다. 차단 규칙은 다음 호출부터 적용됩니다.
- 서버는 금지 사이트의 기록을 "페이지 읽음"으로 인정하지 않습니다. 차단 규칙이 실패해도 확인된 출처가 되지 않습니다.

## 4. 팀 공용 기능의 제한 사항 (수정하지 않음)

아래 기능은 팀 공용 작업이라 수정하지 않았습니다. 같은 이용규약 조항에 해당할 수 있으니 팀에서 결정이 필요합니다.

| 기능 | 위치 | 제한 사항 |
| --- | --- | --- |
| 공식 상품 URL 수집 | `scripts/fetch_product.py` | 치이카와 마켓의 상품 JSON, 상품 페이지, 이미지를 자동으로 받습니다. 429가 나면 대기 후 1회 재시도합니다 |
| User-Agent | `scripts/fetch_product.py` | `Mozilla/5.0 (semogwi fetch_product)`. 프로그램 이름이 있지만 브라우저 표기로 시작합니다 |
| URL 입력 흐름 | `.claude/commands/cardnews.md`, `.claude/skills/analyze-image/SKILL.md` | 공식 상품 URL이 입력되면 위 스크립트를 실행하도록 되어 있습니다 |
| `research-topic`의 추가 조사 | `.claude/skills/research-topic/SKILL.md` | 공식 스토어를 웹에서 찾을 수 있다고 되어 있고, 금지 사이트 구분이 없습니다 |
| 기존 산출물 | `projects/` 일부 | 위 방식으로 받은 상품 정보와 이미지가 들어 있습니다. 공개 게시는 별도 판단이 필요합니다 |

**권장 결정 사항**
1. 허가를 받을 때까지 URL 입력 흐름을 쓸지 정합니다.
2. 쓰지 않는다면 Skill과 커맨드에 안내를 추가합니다.
3. 허가를 받으면 범위를 기록하고, User-Agent를 프로그램임이 분명한 값으로 바꿉니다.

**이번에 수정한 범위:** `web/`만 수정했습니다. 위 기능의 동작은 그대로이며, `/cardnews`를 직접 실행하면 여전히 쇼핑몰에 접속합니다.
