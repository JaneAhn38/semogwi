# 고정 템플릿 규격 (작업 형식 3)

팀이 만든 PNG 디자인 20장(`templates/reference/`, 4유형 × 5장)을 편집 가능한 템플릿 JSON으로 옮긴 것입니다. 디자인과 배치는 고정이고, 필드 값과 이미지만 바뀝니다. AI는 문구와 사실만 쓰고 좌표를 만들지 않습니다.

PNG는 시각 기준으로만 씁니다. 배경으로 깔고 글자를 덮어쓰지 않습니다. 원본 편집 파일(Figma, SVG 등)은 프로젝트에 없어서, 글자·도형·이미지를 모두 독립 요소로 다시 그렸습니다.

| 파일 | 역할 |
| --- | --- |
| `templates/<유형>-01.json` ~ `-05.json` | 카드별 디자인 요소와 필드 정의 (20개) |
| `templates/character-cover.json`, `character-body.json` | 예전 형식 3 작업(표지 + 본문 반복)을 열 때만 씀 (`legacy`) |
| `app/templates.py` | 템플릿 검사, 필드 정리·검사, AI 출력 형식과 규칙 생성, 카드 명세 생성 |
| `static/renderer.js` `renderTemplate` | 같은 JSON으로 미리보기와 PNG를 그림 |

## 유형별 5장

| 유형 (색) | card-01 | card-02 | card-03 | card-04 | card-05 |
| --- | --- | --- | --- | --- | --- |
| 캐릭터 소개 (핑크) | 표지 | 프로필 | 성격과 특징 | 친구와 TMI | 마무리 |
| 굿즈 판매 (옐로) | 표지 | 라인업 한눈에 | 주목할 굿즈 | 구매 방법 | 마무리 |
| 콜라보 (블루) | 표지 | 어떤 콜라보 | 제품·메뉴 | 혜택·이벤트 | 마무리 |
| 팝업스토어 (민트) | 표지 | 운영 정보 | 현장 한정 굿즈 | 포토존·특전 | 마무리 |

작업을 시작할 때 유형의 5장을 골라 `job.templateSet`에 저장합니다. 템플릿 파일이 바뀌어도 이미 만든 작업은 같은 id로 그립니다.

## 템플릿 JSON

좌표는 1080×1350 기준입니다. 참고 PNG(2160×2700)의 절반입니다.

```json
{
  "id": "character-02", "contentType": "character", "kind": "body", "label": "프로필",
  "reference": "reference/캐릭터 소개 · 02 프로필.png",
  "fonts": { "display": "Jua", "body": "Gowun Dodum" },
  "palette": { "bg": "#FFF8F0", "ink": "#2E2A35", "accent": "#F7C6D3" },
  "inherit": [],
  "fields": [ { "key": "character_name", "label": "이름", "type": "text", "max": 12, "required": true, "item": "name" } ],
  "images": [ { "key": "character_image", "label": "캐릭터 이미지", "required": false } ],
  "elements": [ { "type": "text", "field": "character_name", "box": { "x": 72, "y": 182, "w": 936, "h": 84 }, "font": "display", "size": 64 } ],
  "sample": { "source": "출처: [공식 계정]", "fields": { "character_name": "[캐릭터 이름]" } }
}
```

- `sample`은 참고 PNG와 같은 자리표시 문구입니다. 비교 검증에만 쓰고 화면에는 보내지 않습니다.
- 필드의 `item`은 그 필드를 채우는 조사 항목입니다 (`app/research.py`의 유형별 목록). 서버 시작 시 목록에 있는 항목인지 검사합니다.
- 필드에 `"demo": ""`를 두면 데모에서 그 값으로 채웁니다 (예: 프로필 번호는 데모에서 비움).
- `inherit`은 표지(card-01)의 값을 그대로 보여 줄 필드입니다 (예: 콜라보 본문의 "브랜드 × 캐릭터"). 그 카드에서는 고치지 않습니다.

### 필드 형식

| type | 값 | 제한 |
| --- | --- | --- |
| `text` | 문자열, 줄바꿈 없음 | `max` |
| `multiline` | 문자열, 최대 2줄 | `max` |
| `list` | 문자열 배열 (태그, TMI, 입장 팁) | `maxItems`, `itemMax` |
| `items` | 객체 배열 (상품, 친구, 혜택). 하위 필드는 text·multiline | `maxItems`, 하위 필드의 `max`, `required` |
| `flag` | 참·거짓 (신상품 여부) | 출처로 확인된 경우에만 켬 |
| `pairs` | `[{label, value}]` | 예전 형식 3 템플릿에서만 씀 |

`required`가 아닌 필드는 비우면 카드에서 숨깁니다. 확인되지 않은 정보를 채우지 않기 위해서입니다. 반복 항목은 비운 칸의 카드(테두리, 사진 자리, 번호)를 함께 숨깁니다.

### 요소

| type | 설명 |
| --- | --- |
| `header` | 세모귀 로고·글자, 오른쪽 유형 태그 |
| `footer` | 왼쪽 문구(`left` 또는 `parts`를 " · "로 이음), 오른쪽 `01 / 05`. `dy`로 높이 조정 |
| `rect`, `circle`, `line` | 면과 선. `radius`는 숫자 또는 `[좌상, 우상, 우하, 좌하]`, 선은 `dash` 가능 |
| `text` | `field`(필드 경로, 예: `traits.0.keyword`) 또는 `text`(고정 문구, `{필드}` `{source}` `{source_text}` 치환) |
| `pill` | 글자 길이에 맞춰 너비가 정해지는 알약·배지. `align` left·center·right, `icon: "pin"` |
| `image` | 이미지 자리 `slot`. 원본 비율 유지(contain). `shape: "circle"`, `rotate`(기울인 액자) |
| `rows` | 고정 이름 + 필드 줄. 빈 줄은 위로 당김 |
| `chips`, `bullets` | 목록 필드를 태그나 글머리 줄로 |
| `star` | 별 배지 (NEW, PICK) |
| `check` | 체크 아이콘 |
| `asset` | 세모귀 마스코트 그림 |

모든 요소에 `"if": "필드 경로"`를 붙이면 값이 비었을 때 그리지 않습니다. 글자는 칸에 맞을 때까지 `minSize`까지 줄이고, 그래도 넘치면 넘친 필드를 알립니다.

서버를 시작할 때 템플릿을 검사합니다. 다음 경우에는 서버가 시작하지 않습니다.
- 없는 필드나 이미지 자리를 그림
- 범위를 벗어난 항목 번호를 씀
- 고정 문구에 자리표시가 있음
- 세트 안에서 같은 이름의 필드 형식이 다름

## 유형 판단

| 상황 | 방법 |
| --- | --- |
| 사용자가 유형을 고름 | 그대로 씀 |
| "AI가 판단" + 실제 AI | 조사 전에 웹 도구 없는 짧은 호출 1회(`classify`)로 고름 |
| "AI가 판단" + 데모, 또는 자동 접근 금지 사이트 | AI를 부르지 않고 주제의 키워드로 추정 |

구성안 단계에서 유형을 바꿀 수 있습니다. 실제 AI 작업은 저장된 조사 결과로 5장을 다시 쓰고(호출 1회, 검색 없음), 데모는 예시 내용으로 바꿉니다. 직접 고친 내용, 이미지 지정, 승인은 초기화됩니다.

## 조사 항목 (`app/research.py`)

실제 AI 조사는 유형별 항목 목록(체크리스트)을 받아, 항목마다 값·근거 문장(80자 이내)·출처 번호를 냅니다. 찾지 못한 항목은 빈 값으로 냅니다. 서버가 도구 기록과 대조해 항목 상태를 정합니다.

| 상태 | 뜻 |
| --- | --- |
| 공식 확인 (`verified`) | 공식 출처 페이지를 실제로 읽음 |
| 2차 자료 (`secondary`) | 위키·기사 등 공식이 아닌 페이지를 실제로 읽음. 엄격 항목(가격, 일정, 장소, 혜택 등)이면 승인 차단 |
| 사용자 제공 (`user`) | 입력 화면의 **참고 자료 직접 입력**(출처 `u1`)이나 자료 입력 화면에서 받은 내용 |
| 검색 목록만 (`listed`) / 근거 없음 (`unverified`) | 페이지를 읽지 않음. 확인된 정보로 표시하지 않음 |
| 출처 충돌 (`conflict`) | 같은 항목에 서로 다른 값이 있음. 값을 모두 보여 주고 사용자 확인을 기다림 |
| 정보 확인 필요 (`missing`) | 찾지 못함. 카드에서 숨기거나(선택 필드) 사용자에게 입력을 요청(필수 필드) |

- 같은 값(공백·기호 차이 무시)은 하나로 합치고 출처를 모읍니다. 사실(facts) 목록도 중복을 없앱니다.
- 일반 상식은 근거로 쓰지 않도록 프롬프트로 막고, 출처 없는 값은 `unverified`가 됩니다.
- 검색 도구 오류와 결과 없는 검색은 `research.searchFailures`, 접속 실패는 `fetchFailures`, 금지 사이트는 `policyStops`에 나눠 기록합니다. 화면의 "조사 중 문제"에 이유별로 보여 줍니다.
- 구성안 필드마다 `outline.fieldStates[frame][key]`에 상태를 두고 배지로 보여 줍니다. 조사 결과 화면에서 **카드에서 입력**을 누르면 그 항목을 쓰는 카드 편집으로 이동합니다.
- 조사 항목의 이용 한도: 검색 6회, 페이지 읽기 5회, 시간 10분, 비용 상한 3.0(구독 한도 추정치).

## 검사와 승인

| 상황 | 처리 |
| --- | --- |
| 필수 필드가 비어 있음 | 구성안 승인 차단. AI에게 다시 쓰게 하지 않고 사용자에게 입력을 요청 |
| 엄격 항목이 출처 충돌·2차 자료·검색 목록만·근거 없음 | 구성안 승인 차단. 사용자가 그 카드를 직접 고치면 경고로 바뀜 |
| 글자 수·개수 초과 | 저장·승인 차단. AI 결과는 한 번만 다시 쓰게 함 |
| `[캐릭터 이름]`, `MM월 DD일` 같은 자리표시 | 저장·승인 차단 |
| 굿즈·콜라보·팝업에서 자료에 없는 숫자(가격, 날짜) | 한 번 다시 쓰게 하고, 남으면 승인 차단 |
| 그려 보니 칸을 넘침 | 미리보기 아래 안내, 구성안·최종 승인 버튼 잠금 |
| 필수 이미지(표지 등) 비어 있음 | 미리보기 아래 안내. 실제 AI 작업은 최종 승인 차단, 데모는 안내만 |
| 출처 검증 | 기존 규칙 그대로 (`docs/site-access-policy.md`) |

## 비교 검증

각 템플릿을 `sample`로 그려 참고 PNG와 겹쳐 봤습니다. 다른 픽셀(색 차이 40 초과) 비율은 20장 모두 1.5~4.3%입니다.

남은 차이:
- 참고 PNG의 점선 이미지 자리와 "공식 이미지" 같은 안내 글자는 그리지 않습니다. 빈 이미지 자리는 흐린 세모귀로 채웁니다.
- 참고 PNG는 단어 중간에서도 줄을 바꾸지만("확인/된"), 렌더러는 띄어쓰기 단위로 바꿉니다.
- 글자 위치는 3px, 너비는 6px 안쪽으로 맞췄습니다.

팀의 HTML 템플릿(`semogwi-cardnews-templates/templates/*.html`, 수정하지 않음)도 같은 자리표시로 그려 비교했습니다. HTML ↔ 참고 PNG 0.4~2.9%, HTML ↔ 웹 캔버스 1.2~4.3%입니다. HTML의 모든 `data-slot`은 웹 필드에 대응합니다 (일부는 나뉨: 캐릭터 첫 등장은 `debut_year` + `debut_work`). 웹은 빈 칸 숨김, 글자 자동 축소, 넘침 감지가 필요해서 HTML 파일을 그대로 쓰지 않고 같은 디자인의 캔버스 템플릿을 씁니다.
