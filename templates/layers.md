## 2. 레이어별 역할

| 레이어명 | 역할 | 유형 | 자동화 여부 |
| --- | --- | --- | --- |
| `title` | 카드별 제목 | 텍스트 (Jua) | ✅ 자동화 대상 |
| `body` | 카드별 본문 | 텍스트 (Gowun Dodum) | ✅ 자동화 대상 |
| `main-image` | 캐릭터 이미지 | 이미지 | 🔜 추후 자동화 대상 |
| `page-number` | 페이지 번호 | 텍스트 | ⏸ 현재 고정 |
| `source` | 카드별 자료 출처 | 텍스트 | ✅ 자동화 대상 |
| `bottom-overlay` | 하단 그라데이션 | 도형 / 그라데이션 | 🔒 고정 |

### 레이어 상세

- **title**
  - 각 카드의 핵심 메시지를 담는 제목 텍스트입니다.
  - 폰트: Jua
  - 자동화 시 텍스트 길이에 따른 줄바꿈·넘침 여부를 확인해야 합니다.

- **body**
  - 제목을 보충하는 본문 텍스트입니다.
  - 폰트: Gowun Dodum
  - 문장 길이가 카드마다 다르므로 최대 글자 수 기준을 정해 두는 것이 좋습니다.

- **main-image**
  - 카드의 중심이 되는 캐릭터 이미지입니다.
  - 현재는 수동으로 배치하며, 추후 이미지 경로 또는 URL을 받아 교체하도록 자동화할 예정입니다.

- **page-number**
  - 카드 순서를 표시합니다 (예: 1/5).
  - 현재는 프레임별로 고정된 값을 사용합니다.

- **source**
  - 카드에 사용된 자료의 출처를 표시하는 텍스트입니다 (예: `출처: ○○○`).
  - 카드마다 출처가 다를 수 있으므로 자동화 대상으로 둡니다.
  - 출처가 길어질 수 있으므로 최대 글자 수와 줄바꿈 기준을 정해 두는 것이 좋습니다.
  - 템플릿에 지금 적혀 있는 `@세모귀`는 브랜드 표기가 아니라, 출처가 정해지지 않아 넣어 둔 **임시 텍스트**입니다. fill-figma는 이 레이어를 그대로 두고 `slides.json`의 `source` 값으로 텍스트만 교체합니다. 브랜드 표기용 레이어는 따로 만들지 않습니다.

- **bottom-overlay**
  - 하단 텍스트 가독성을 높이기 위한 그라데이션 레이어입니다. 모든 카드에서 동일하게 유지됩니다.

## 3. 프레임 구조

5개 프레임은 모두 같은 레이어 구성을 따르며, 레이어는 아래 **6개로 고정**합니다. 자동화 과정에서 레이어를 새로 추가하거나 지우지 않습니다.

```
card-01 ~ card-05  (Frame, 1080 × 1350)
├── title            # 제목 (Jua)              — 자동화
├── body             # 본문 (Gowun Dodum)      — 자동화
├── main-image       # 캐릭터 이미지           — 추후 자동화
├── page-number      # 페이지 번호             — 현재 고정
├── source           # 자료 출처               — 자동화
└── bottom-overlay   # 하단 그라데이션         — 고정
(배경: 파스텔 그라데이션)
```

> 참고: 위 트리는 레이어 목록을 정리한 것이며, Figma 안의 실제 쌓임 순서(z-order)와 다를 수 있습니다. 자동화 스크립트는 순서가 아니라 **레이어 이름**으로 노드를 찾는 것을 원칙으로 합니다.

| 프레임 | 용도 |
| --- | --- |
| `card-01` | 1번 카드 |
| `card-02` | 2번 카드 |
| `card-03` | 3번 카드 |
| `card-04` | 4번 카드 |
| `card-05` | 5번 카드 |

### 네이밍 규칙

- 프레임 이름: `card-` + 두 자리 번호 (`card-01` ~ `card-05`)
- 레이어 이름: 소문자 + 하이픈(kebab-case)
- 자동화 스크립트가 이름으로 레이어를 찾으므로, **프레임·레이어 이름은 임의로 바꾸지 않습니다.**

## 5. slides.json 규격 (MVP 확정)

> ✅ 2026-10-27 확정. write-copy Skill이 이 규격으로 `slides.json`을 만들고, fill-figma Skill이 이 규격으로 읽습니다. 바꿀 때는 두 Skill과 이 문서를 함께 수정합니다.

### 5.1 구조

```json
{
  "series": "세모귀",
  "topic": "치이카와 서사 정리",
  "character": "chiikawa",
  "slides": [
    {
      "frame": "card-01",
      "title": "제목 (20자 이내)",
      "body": "본문 (80자 이내)",
      "source": "출처: 치이카와 공식 X",
      "image": "assets/characters/chiikawa/cutout/chiikawa-01.png"
    }
  ]
}
```

- `slides`는 **항상 5개**이며, 순서대로 `card-01` ~ `card-05`에 대응합니다.
- `card-01`은 표지, `card-02` ~ `card-05`는 본문 카드입니다.

### 5.2 필드 규칙

| 필드 | 대상 레이어 | 필수 | 규칙 |
| --- | --- | --- | --- |
| `series` | - | ✅ | 항상 `"세모귀"` |
| `topic` | - | ✅ | 이번 카드뉴스 주제 |
| `character` | - | ✅ | `assets/characters/` 아래 폴더 이름과 같게 (예: `chiikawa`) |
| `slides[n].frame` | 프레임 | ✅ | `card-01` ~ `card-05` 중 하나, 중복 불가 |
| `slides[n].title` | `title` | ✅ | **20자 이내** (공백 포함), 줄바꿈 금지. 한 줄에 들어가도록 **16자 이하 권장** (6장) |
| `slides[n].body` | `body` | ✅ | **80자 이내** (공백 포함, `\n` 제외), 1장 1메시지. 42자를 넘으면 띄어쓰기 위치에 `\n`, 최대 2줄 (6장) |
| `slides[n].source` | `source` | 선택 | **30자 이내**, `출처: ` 로 시작, 줄바꿈 금지. 비어 있으면(`""`) 레이어 숨김 |
| `slides[n].image` | `main-image` | 선택 | `cutout/` 폴더의 누끼 이미지 경로. MVP에서는 `card-01`만 사용. 이미지가 없으면 `""` |

- 글자 수를 넘기면 write-copy 단계에서 줄여서 다시 씁니다. fill-figma는 넘친 텍스트를 자르지 않습니다.
- `image`에 쓰는 이미지는 반드시 `sources.md`에 출처가 기록되어 있어야 합니다.
- 규격 검사는 `py scripts/fill_figma.py validate <slides.json>`으로 합니다. write-copy도 slides.json을 만든 뒤 같은 명령으로 확인할 수 있습니다.

### 5.3 연결 흐름

1. `projects/날짜_주제/slides.json`을 읽습니다.
2. 같은 Figma 파일 안에 새 페이지(`세모귀_<프로젝트 폴더 이름>`)를 만들고 원본 `Page 1`의 `card-01` ~ `card-05`를 그 페이지로 복제합니다. 같은 이름의 페이지가 있으면 중단합니다. 이후 단계는 **새 페이지 안에서만** `frame` 값으로 프레임을 찾습니다. 원본 `Page 1`은 건드리지 않습니다.
3. 프레임 안의 `title`, `body`, `source` 레이어 텍스트를 교체합니다. `source`가 비어 있으면 레이어를 숨깁니다.
4. `card-01`에 `image`가 있으면 `main-image`의 이미지 채우기를 **FIT**(전체 보임, 잘림 없음) 방식으로 교체합니다.
5. 고정 레이어(`page-number`, `bottom-overlay`)와 배경은 건드리지 않습니다.
6. 각 프레임을 1080 × 1350 px PNG로 `projects/날짜_주제/png/card-01.png` ~ `card-05.png`에 내보냅니다.

자세한 실행 절차는 `.claude/skills/fill-figma/SKILL.md`를 따릅니다.

## 6. 레이아웃 규칙 (2026-10-29 테스트 결과)

테스트 카드 5장을 실제 템플릿에 넣어 측정한 값입니다. 폰트·크기·레이어 위치가 바뀌면 다시 측정합니다.

### 6.1 측정값

| 레이어 | 폰트 / 크기 | 위치·크기 | 관찰 |
| --- | --- | --- | --- |
| `title` | Jua 80px | x 60, y 1000, 너비 960, 1줄 높이 100 | 14자(공백 포함)가 약 800px → 한 줄에 약 16자 |
| `body` | Gowun Dodum 28px | x 60, y 1150, 너비 960, 1줄 높이 약 41 | 45자는 한 줄, 47자에서 줄바꿈 |
| `source` | Jua 28px | x 60, y 40, 너비 자동 | 15자 기준 오른쪽 끝 340 (page-number는 870부터) |

### 6.2 제목 겹침 방지

- 제목은 **한 줄**이어야 합니다. 2줄이 되면 높이가 200이 되어 아래 끝(1200)이 body 위 끝(1150)을 넘어 겹칩니다.
- 그래서 제목은 **16자 이하**로 씁니다 (규격 한도 20자는 그대로). 17 ~ 20자는 validate가 경고하고, fill-figma의 Figma 검사에서 2줄이 되면 중단합니다.
- 제목에는 `\n`을 넣지 않습니다.

### 6.3 본문 줄바꿈

- Figma는 한글을 **글자 단위**로 줄바꿈하므로, 긴 본문은 단어 중간에서 끊깁니다 (예: "시작됐 / 어요.").
- 본문이 **42자를 넘으면** write-copy가 띄어쓰기 위치에 `\n`을 넣어 직접 줄을 나눕니다. 각 줄은 42자 이하로 맞춥니다 (실측 45자에서 여유를 둔 값).
- 본문은 **2줄 이하**로 씁니다. 줄 앞뒤에 공백을 남기지 않습니다.
- 글자 수 80자에는 `\n`을 세지 않습니다.

### 6.4 fill-figma가 Figma에서 검사하는 항목

텍스트를 넣은 뒤 실제 레이아웃을 읽어 아래 항목을 확인하고, 하나라도 어기면 중단합니다.

| 검사 | 기준 |
| --- | --- |
| 제목 줄 수 | 넣은 뒤 높이가 템플릿 1줄 높이(100)를 넘지 않음 |
| 제목-본문 간격 | title 아래 끝 + 20 ≤ body 위 끝 |
| 본문 하단 여백 | body 아래 끝 ≤ 1350 − 60 |
| 출처-페이지 번호 | source 오른쪽 끝 + 20 ≤ page-number 왼쪽 끝 (source가 보일 때) |
| 너비 | 모든 텍스트가 프레임 너비 1080 안 |
| 고정 요소 | page-number·bottom-overlay·main-image·배경이 교체 전후 동일 |
| 본문 줄 수 | 2줄 초과 시 경고 |

텍스트를 넣기 **전에** (preflight, 읽기 전용) 아래 전제도 확인합니다. 어긋나면 템플릿이 바뀐 것이므로 6.1을 다시 측정합니다.

| 전제 | 기준 |
| --- | --- |
| 텍스트 크기 조절 | `title`·`body`가 너비 고정 + 높이 자동(`HEIGHT`). 그래야 줄 수가 높이로 드러남 |
| 자리표시 제목 | 템플릿 `title` 높이가 1줄 기준(100)의 1.5배 이하 |
